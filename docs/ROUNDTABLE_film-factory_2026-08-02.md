## 開桌：問題釘死

**「製片工廠 v1 的管線該長什麼樣（需求→分鏡表→分鏡圖→切片→成片各站怎麼設計），第一吋切哪裡？」**

## 共同案卷（全員同讀）

**Adam 的願景**：使用者提出需求後，系統模擬導演與製片角色，自動化完成——①生成完整性夠的分鏡表與分鏡圖 ②自動切片並產生關鍵影格 ③串聯 prompt 達到全系列自動化。從 UDN 平台的 video 功能抽出，設計成獨立「製片工廠流」。

**現場調查（2026-08-02，UDN platform）**：
- 四條活產線：懶人包（文案→拆卡→STYLE BIBLE 視覺母版→gpt-image-2 無字底圖→sharp 確定性壓字）；scene_video（人選 1-10 張圖卡→人手寫轉場/運鏡註解→Veo 3.1 首尾幀逐段生成→ffmpeg 拼接，斷點續跑＋每段記帳）；HeyGen 數位人；Podcast（Haiku 場控挑說話者＋下戲劇動作、Sonnet 演角色逐輪——**「模擬導演」的家內先例**）。
- 缺口：分鏡表/分鏡圖引擎整區不存在（今天的導演＝使用者本人）；自動切片＋關鍵影格不存在；prompt 全鏈串聯半成品（STYLE BIBLE＋首卡參考圖串接已有，需求→劇本→分鏡→影格→影片全鏈無）。
- 耦合：媒體引擎全部通用、env 驅動（Veo/gpt-image/HeyGen/MiniMax/ffmpeg/sharp）；耦死的只有 Brief/對話/角色庫/額度這層前台。

**硬約束（實戰驗證過）**：
- Veo 3.1 首尾幀模式＝固定 8 秒/段（4/6 不支援）；單圖 image-to-video 可 4/6/8 秒；9:16 支援 720p/1080p（1080p 限 8 秒）；聲音永遠開啟；Vertex us-central1；輪詢 fetchPredictOperation。
- 計價（成功才計費）：fast 720p $0.10/s、fast 1080p $0.12/s、standard $0.40/s。前例：10 段上限＝$7.2 封頂。
- RAI 內容過濾會隨機擋敏感素材（同圖同判定穩定重現、被擋不收費）。
- gpt-image-2 畫中文字會變形→文字層一律 sharp 確定性壓字（架構反轉已驗證）。
- 築的天條：確定性工作用程式不丟 LLM；長任務進 Cloud Run Jobs；蓋平台先鋪地基帳本。

## 盲答立論（各自獨立脈絡寫成，互相看不到；築的先於派神寫定）

### 築（施工/監造）——盲答

**立場**：v1 管線七站，其中五站是搬現成建材：
①**需求單站**——一句話的片子（給誰看/什麼感覺）＋格式（9:16 或 16:9）＋長度＋**預算封頂**（製片帳從第一站就在）。
②**導演站**（新蓋，核心）——LLM 把需求拆成敘事結構，產出**分鏡表 JSON**：段序/景別/運鏡/時長（以 8 秒為格律量化）/畫面描述/首尾幀描述/轉場情緒。結構化輸出走 tool-use 強制 schema，秒數與段數用程式驗（確定性歸程式）。家內先例＝Podcast 場控（Haiku 導演＋Sonnet 演員），搬骨架換領域。
③**母版站**——STYLE BIBLE 生成，整支片一份視覺母版（搬懶人包 Phase B）。
④**分鏡圖站**（新蓋一半）——逐段首尾幀生圖：imagePrompt＝分鏡表描述×母版，首張當後續參考圖串接連戲（搬懶人包 Phase C 的參考圖機制）。相鄰段共用幀：段 N 的尾幀＝段 N+1 的首幀，K 段只生 K+1 張圖。
⑤**人審閘**——分鏡表＋分鏡圖攤給人過目**才准燒 Veo 錢**。圖便宜影片貴，這道閘是錢閘也是品質閘（「點頭才動工」天條的產線版）。
⑥**生成站**——Veo 逐段＋斷點續跑＋每段記帳（搬 scene_video 全套，零改動）。
⑦**成片站**——ffmpeg 拼接＋可選 TTS 旁白軌（搬 audio 線）。

**第一吋**：不先蓋新平台。先在 UDN 現址把「導演站＋分鏡圖站」插進 scene_video 前面——需求→自動分鏡表→自動生首尾幀→自動填 Video Studio 的卡與轉場註解，跑出第一支全自動片。引擎本來就通用，抽成獨立平台是第二步（換前臉），先驗「導演的判斷夠不夠好」這個唯一未知數。

**署名準則**：一吋蛋糕先跑真實輸出（walking skeleton 天條）；確定性歸程式（分鏡表 schema/秒數量化/成本計算全程式驗）；樣品屋天條（人審閘＝最晚灌注點在燒錢之前）。

**信心度**：高——七站裡五站是生產環境驗證過的建材，唯一真未知是導演站的判斷品質，第一吋就是衝著它驗的。

### 浩斯（HAUS）——盲答

**一、計畫書摘要**〔佩尼亞〕
- **目標**：把「導演＋製片」從使用者腦裡搬進系統——需求進、成片出，中間每站可審可改。
- **事實**：媒體引擎（Veo、gpt-image-2、sharp、ffmpeg、Jobs）四條產線已是活磚；缺的是**導演的腦**（分鏡表/分鏡圖引擎）與**製片的手**（切片、全鏈 prompt 串聯）。硬約束：Veo 首尾幀固定 8 秒/段、RAI 隨機擋件、成功才計費。
- **概念**：管線不是流水直通，是「**每站產物落地、人審後放行**」的片廠制。
- **需求 vs 願望**：需求＝分鏡表引擎、切片器、串聯層；願望＝全自動零人工——v1 不准假扮需求。
- **問題陳述**：如何讓一份**結構化分鏡表成為唯一真相**，讓下游每站都只讀它、不各自為政。

**二、房間總表**〔亞歷山大攤清單，埃文斯標域〕
1. **接單櫃台**（需求對話→Brief）〔前台/支撐/夠用就好〕
2. **導演房**（分鏡表引擎：場次、鏡頭語言、時長節拍——以 8 秒為原子單位下譜）〔前台/**核心**/自己蓋〕
3. **美術房**（分鏡圖：STYLE BIBLE 母版＋gpt-image-2 無字底圖）〔前台/核心/既有磚改裝〕
4. **剪接台**（切片器：分鏡表→8 秒段序列、首尾幀配對、關鍵影格指派）〔後台/**核心**/自己蓋——這間是 Veo 硬約束的翻譯層，全案最值錢的房間之一〕
5. **生成車間**（Veo 逐段、Cloud Run Jobs、斷點續跑、每段記帳）〔後台/支撐/既有磚〕
6. **拼接房**（ffmpeg 串片）〔後台/通用/既有磚〕
7. **審片室**（每站產物可編輯：分鏡表逐格改、分鏡圖單張重生）〔前台/核心/自己蓋〕
8. **帳房**（開拍前報價：段數×秒數×單價；RAI 擋件不計費的對帳）〔後台/支撐/自己蓋〕
9. **進度看板**（輪詢＋watchdog）〔前台/支撐/既有模式〕

**三、後台補課清單**〔斯克拉——這段不准省〕
- 導演房的後台：**分鏡表 schema 驗證器**——LLM 輸出當不可信文字，程式級 validate/repair，不准 re-ask 模型修。標紅，現不存在。
- 美術房的後台：**單格重生台**——一張爛不能整批重跑。標紅。
- 生成車間的後台：**RAI 擋件處理台**——被擋的段要能改寫 prompt 單段重投，否則一段卡死全片。標紅，現行只有斷點續跑，沒有「換說法重投」。
- 帳房的後台：**預算閘**——超預算先停不先燒。標紅。

**四、血管地圖**〔埃文斯〕
Brief →（導演房）→ **分鏡表 JSON＝主動脈** →（美術房）逐格產圖 →（剪接台）讀表切 8 秒段＋配首尾幀 → 寫 task doc →（生成車間 Jobs）→（拼接房）→ 成片。審片室橫插在每站之後，改動**寫回分鏡表**——不准站與站私傳資料，同一機能只住一間房，否則真相分裂。孤島警告：若分鏡圖不帶回每格的 video prompt，串聯層就斷血管。

**五、砍房清單**〔佩尼亞強制刪減〕
- **多租戶/額度/角色庫**：UDN 耦死的前台層，獨立平台 v1 不搬——砍。
- **配音/TTS/Podcast 接入**：另一條產線，v1 成片默片或後配——砍。
- **HeyGen 數位人**：獨立品種不進本管線——砍。
- **模板市集、自動發布排程、即時預覽渲染**：願望，砍。
- **全自動免審模式**：導演還沒證明會下譜之前，砍——這是原則不是排程。

**第一吋切哪裡**：切**導演房＋審片室的最小組合**——一支需求進、一張可編輯的結構化分鏡表出（schema 驗證過），然後**手動**餵既有 scene_video 線跑出一支真成片。理由〔斯克拉走動線〕：媒體端全是活磚，全案唯一沒被驗證的假設是「LLM 能把需求譯成夠完整的分鏡譜」——第一吋必須直插這個最大風險，且吃到真實輸出才算一吋蛋糕。切片器是第二吋，串聯是第三吋。

**信心度：高**——房間清單建立在現場調查的活磚盤點上，第一吋直指全案唯一未驗證的核心假設，其餘皆是已驗證管道的重新配管。

### 財神（CAISHEN）——盲答

**一、僱用宣言**

〔克里斯坦森〕使用者解雇的是「自己客串的導演」：當我手上有一個要交付的內容需求時，我想要系統把它變成一份我敢直接開拍的分鏡表與分鏡圖，好讓我不必自己逐段手寫轉場運鏡、也不必請真人製片團隊。注意——被解雇的不是 Veo、不是 ffmpeg（現場調查說了，媒體引擎四條產線全活著），是那個今天還卡在人腦裡的「導演判斷」。所以這個平台的本體是**分鏡引擎**，不是影片工廠。工廠早就在了，缺的是廠長。

**二、未來新聞稿（三句）＋FAQ 一問**

「今天起，UDN 議題工作台的用戶丟進一個題目，十分鐘後拿到一份完整分鏡表與分鏡圖，改幾個字、按下確認，成片自己長出來。過去這一步要一個懂運鏡的人坐在螢幕前逐張寫註解，現在那個人只需要當評審。每支片的判斷力都會留下來，系統的導演一天比一天像老手。」

FAQ 一問：**AI 排的分鏡我不滿意怎麼辦？**——答：分鏡表在燒任何一塊錢影片預算之前就攤在你面前，全欄可編輯；你改的每一筆，都是在教下一次的導演。〔貝佐斯〕這條 FAQ 就是飛輪本體：片量多→修正資料多→分鏡引擎準→重跑率降→單片成本降→片量更多。修正資料從第一天就要落庫，這是唯一畫得成環的資產。

**三、定位與灘頭**

〔摩爾〕填空：給**UDN 議題工作台的既有交付用戶**（誰），他有**「會選圖卡但寫不出運鏡註解、每支片卡在導演環節半天」**的痛，我們是**內容產線上的 AI 導演站**（類別），不像**通用文生影片工具**（既有替代）只給你一顆黑盒按鈕，我們**把分鏡表攤開成可審可改的合約，錢在你點頭之後才開始燒**（唯一差異）。

灘頭裁決：**第一批付錢的人已經存在，在 UDN 裡。**threads-radar、manman、ailivex 的影音需求是內需，不是客戶。〔摩爾〕「四個平台都要用」就是海岸線不是灘頭——v1 不抽獨立平台，分鏡引擎以**模組**形式蓋在 UDN scene_video 產線的上游（現場調查已證實：耦死的只有前臉，引擎層本來就通用），介面切乾淨，等第二個**真租戶**出現再付前臉的錢。現在抽出去，是替想像中的用戶蓋大廳。

**四、四風險過堂表**

- **價值 🟡**：scene_video 有人在用是跡象，但「AI 分鏡表好到用戶願意收」只有信仰。最便宜驗證：撈三個**歷史真實案子**，讓引擎盲產分鏡表，跟當時人手寫的註解對放，請原用戶挑——不燒一毛 Veo 錢。〔卡根〕
- **易用 🟡**：一鍵全自動是陷阱；用戶要的是「可改的草稿」不是「可拒的成品」。驗證法同上，看用戶改動比例——改三成叫幫手，改九成叫垃圾。〔卡根×西耶拉〕
- **可行 🟢**：Veo 逐段、斷點續跑、sharp、gpt-image-2 全是打過仗的引擎；分鏡表是 LLM 結構化輸出，分鏡圖走既有底圖線。唯一 🟡 是 RAI 隨機擋件，重試預算要進帳。
- **存活 🟡**：單位經濟算得出來：60 秒 fast 720p 片 COGS 約 $6，加分鏡圖與重試抓 $8-10；UDN 對外交付一支片的收費只要是它的三倍以上就站得住。紅線設計：**人審分鏡閘門前分文不燒**——迭代發生在分鏡層（分錢級），不是影片層（美元級）。獨立平台版的存活是 🔴：第一個外部付費者連臉都還沒有。〔卡根×貝佐斯〕

**五、第一吋與不做清單**

**第一吋**：「需求→分鏡表」單站，接進 scene_video 既有的人手註解欄位——AI 產、人來改、改動全記錄。切這裡的理由：它同時拆掉價值風險（用戶收不收）與存活風險（重跑成本壓在便宜層），且三個歷史案子一週內可驗完。〔合議〕

**不做清單**：①不蓋獨立平台前臉（Brief/角色庫/額度/計費）——等第二個真租戶點名再蓋，代價是晚幾個月的「平台感」，換到的是不替幽靈用戶施工；②不做無人閘門的全自動串聯——閘門是商業模式不是妥協；③不碰 standard $0.40/s 檔——品質溢價等有人抱怨 720p 再說；④自動切片與關鍵影格排後，觸發條件：分鏡表站驗收通過、用戶開始抱怨「圖卡還要自己挑」那一天。〔卡根×貝佐斯〕

〔財神合議〕一句收束：**工廠已經在運轉，別再蓋廠房——先僱一個導演，讓現有客戶告訴你他及不及格。**

信心度：**高**——引擎層可行性有四條活產線與實測計價背書，唯一真賭注（分鏡表品質）已被第一吋壓到一週、零 Veo 成本可驗的規模。

### 黑澤（KUROSAWA）——盲答

**一、一句話的片子（系統要產的片型）**

〔黑澤明〕v1 不是「影片工廠」，是「**30–60 秒、9:16 直式、單一敘事線、無對白人物的系列短片**」工廠。片型不先釘死，分鏡表欄位就無從定義——欄位是片型的骨。〔希區考克〕系統的第一站不是分鏡表，是**劇本桌**：使用者需求進來，模擬導演必先產出三行——這支片講什麼（一句話）、給誰看、看完該有什麼感覺。這三行答不出來，後面全部不准動。Podcast 場控已驗證「模擬導演」可行，但那是挑說話者；這裡導演的第一職責是**資訊設計**：觀眾第一秒看到什麼、下一個畫面為什麼是它。

**二、分鏡表（v1 欄位規格＋30 秒示例）**

〔黑澤明〕分鏡表就是電影本身的第一次存在，v1 的表是**機器可驗證的 schema**，每段七欄：

1. **景別**（特寫/中景/遠景——enum，不准自由發揮）
2. **運鏡**（英文，直接餵 Veo：slow push-in、orbit 等）
3. **時長**（固定 8，程式驗證：非 8 的倍數直接退件）
4. **畫面描述**（英文 prompt 本體，帶 STYLE BIBLE 母版前綴)
5. **轉場理由**（中文，寫**觀眾此刻該感覺什麼**，不是畫面怎麼飛）〔莫奇〕
6. **首幀描述**／7. **尾幀描述**（生分鏡圖用；相鄰段共用——段 N 尾幀＝段 N+1 首幀，所以 4 段片只需 **5 張關鍵影格**，不是 8 張）

示例——《一杯手沖咖啡的誕生》32 秒（無人物，避 RAI、避人臉連戲，這是資產清單內拍得起的題材〔羅德里格茲〕）：
- 段1｜特寫｜slow tilt down｜8s｜豆入磨豆機｜「好奇：這是什麼」｜首幀=靜置豆粒、尾幀=**粉落定**
- 段2｜特寫｜push-in｜8s｜熱水注入粉層膨脹｜「屏息：儀式開始了」｜首幀=段1尾幀
- 段3｜中景｜orbit｜8s｜咖啡滴落玻璃壺｜「滿足：等待有了回報」

〔黑澤明〕任何一欄空白＝這鏡還沒想清楚，不准進生成——這條要做成程式閘門，不是導演自律。

**三、連戲與母版**

〔希區考克〕STYLE BIBLE 機制直接繼承為第二站：母版一次生成、逐段 prompt 完整帶入。連戲的關鍵洞察是：**首尾幀要畫「動作的休止符」，不是動作中的瞬間**——尾幀必須是穩定狀態（粉已落定、杯已置好），因為它同時是下一段的起點；畫一張動態模糊的尾幀，Veo 接不起來。〔莫奇〕切點六準則裡連戲只佔 4%、情緒佔 51%：v1 的自動切片站只做硬切（hard cut），共用幀已保住物理連續，剩下的連戲瑕疵**不值得花錢重拍**——轉場理由欄的情緒線斷了才需要重拍。

**四、製片帳**

〔羅德里格茲〕封頂在第一鏡之前訂：v1 每片兩檔——**草稿檔 fast 720p**（32 秒＝$3.2）給人驗收，**成片檔 standard**（$12.8）驗收過才拍。單片封頂 $20，含 RAI 重試（被擋不收費，重試是免費的，但同 prompt 重試超過 3 次＝題材有問題，回分鏡桌改寫，不是硬撞）。生成站唯一允許的「決定」是重試；改 prompt 內容＝創作決定＝回分鏡桌〔希區考克〕。

**五、砍鏡清單（v1 不拍的，逐鏡署名）**

1. **對白與人物 lip-sync**——人臉連戲＋RAI 雙重地雷，v1 的片型直接繞開〔羅德里格茲〕
2. **4/6 秒混拍**——固定 8 秒是格律不是限制，混拍讓切片數學複雜三倍〔羅德里格茲〕
3. **LLM 自動品管重拍迴圈**——拿模型評模型是把驗收交給機率；v1 人眼驗草稿檔〔希區考克〕
4. **轉場特效**（dissolve/wipe）——情緒對了硬切就夠，情緒不對特效救不了〔莫奇〕
5. **配樂旁白後製站**——Veo 原生聲音先用，後製是 v2 的房間〔黑澤明〕

**第一吋切哪裡**：**分鏡表引擎＋人工核可閘＋一支 32 秒草稿檔走完全線**。理由〔黑澤明〕：五站裡分鏡表是「電影第一次存在」的地方，它的 schema 對了，下游全是翻譯；schema 錯了，下游全是垃圾。第一吋必須含人工核可（導演簽字才開機），自動化核可是最後一吋，不是第一吋。

信心度：**高**——8 秒格律、共用幀、計價全是實戰驗證過的物理限制，分鏡表欄位是從格律反推的必然結構；唯一中信心處是模擬導演產表的完整性需首戰實測，故第一吋才釘人工核可閘。

**挑戰二：財神的紙上比稿驗不到片子能不能接起來**

財神的最便宜驗證：「**撈三個歷史真實案子，讓引擎盲產分鏡表，跟當時人手寫的註解對放，請原用戶挑——不燒一毛 Veo 錢**」。

〔黑澤明〕分鏡表不是散文，是拍攝指令；它的及格線不是「讀者投票喜歡哪份」，是「機器接不接得起來」。紙對紙的比稿驗得到語感，驗不到本席盲答裡那條物理律：尾幀必須是動作的休止符，否則 Veo 接不上。一份讀起來漂亮、每個尾幀都停在動態中的分鏡表，在紙上會贏得投票，在機器裡會產出四段各自為政的廢片。何況財神自己說用戶「會選圖卡但寫不出運鏡註解」——請寫不出運鏡的人當運鏡的評審，飛輪灌進去的修正資料是客戶筆記，不是導演功課；拿它教導演，教出來的是討好者。**賭注**：財神對我錯，我多燒 $9.6（三份表各拍一支 32 秒 fast 720p 草稿）；我對財神錯，紙上驗收通過的引擎上線後成片接不起來、重跑率爆炸，他那條「重跑率降→成本降」的飛輪第一圈就斷鏈。修法便宜得很：比稿照做，但每份表**必拍草稿檔**，讓 Veo 投最後一票。

**挑戰三（短打）：築的「可選 TTS 旁白軌」**

築的成片站：「**ffmpeg 拼接＋可選 TTS 旁白軌（搬 audio 線）**」。〔希區考克〕「可選」二字就是把創作決定推遲到成片之後。有旁白的片，畫面描述、節奏、段數在分鏡桌上就長得不一樣——旁白斷句決定畫面斷句。v1 要嘛片型含旁白、分鏡表加旁白欄，要嘛砍掉；掛一個開關，交付的必是畫面一套節奏、旁白一套節奏的兩張皮，還疊在 Veo 永遠開啟的原生聲音上，連混音站都沒有。**賭注**：築對我錯，少一個開關；我對築錯，第一批開了開關的片全是次品。

**立場更新**

改了一處：第一吋的分鏡圖不再堅持自動生成進吋內——築與浩斯盤出的建材帳讓我看清，懶人包線手動跑首尾幀圖已夠第一吋用，自動分鏡圖站是第二吋。〔羅德里格茲〕有現成的就用現成的，這是我自己的戒律，收下。

沒改的：七欄 schema、無人物片型釘死、草稿/成片兩檔封頂制、砍鏡五項——以及最硬的一條：**第一吋必含一支真的拍出來的草稿片**。三尊裡兩尊想把驗收停在紙上（財神紙對紙、浩斯「手動餵」是順帶不是驗收標準），本席不退：紙上沒有的東西機器裡不會有，但紙上有的東西，也要機器點頭才算存在。

信心度：高——兩個主攻都打在他尊自己的原則反身處（浩斯的真相分裂、財神的用戶畫像），不是立場之爭是邏輯之爭。
