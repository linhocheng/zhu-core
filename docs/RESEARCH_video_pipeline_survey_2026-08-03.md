# AI 影片生成主流工作流調查（2026-08-03）

> 三路平行研究：國際主流管線／角色場景一致性技術／中文圈實戰生態。
> 觸發：Adam 測 DreamF 時問「母片會不會出」，判斷現行架構的母片時序可能反了，改寫前先看世界。
> 本檔是三份 agent 報告的濃縮存底＋DreamF 對照。原始完整報告在 session 對話中。

## 一、世界收斂出的標準管線（國際＋中文圈高度一致）

```
劇本鎖定
  → 【鎖一：母資產】角色卡（白底三視圖＋表情＋細節特寫）
                   場景卡（無人、多機位：正打/反打/全景）
                   風格幀＋色票（style frames + palette block）
                   ——影像成本便宜迭代，人工策展選定 hero image 鎖死
  → 分鏡表 / shot list（從母資產渲染，不是從文字憑空生）
  → 【鎖二：逐鏡 keyframe】影像模型把「角色參考＋場景參考」合成單張劇照
  → image-to-video（keyframe 當首幀；或參考圖直進影片模型）
  → 剪輯 / 統一調色（沒人指望生成端 100% 一致，最後一哩靠後期）
```

**業界不變量：「frames before motion, identity before frames」**——動影片額度前，靜態身份資產必先核准。在影像成本迭代身份，在影片成本只迭代動態。

## 二、「母片」的真身（兩種，都不是我們現在做的）

1. **資產母片**（character/location sheet）：一張圖裝正/側/背＋頭部多角度＋細節特寫。新一代模型（Nano Banana 家族）**整張直接當參考圖餵**，官方甚至不建議裁切。生成於分鏡**之前**，是全片的視覺源頭。
2. **九宮格分鏡母圖**（中文圈主流玩法）：參考圖＋prompt → 一張 3×3 全分鏡圖（**同圖生成＝強制一致性**，人物/畫風不跨格漂移）→ 裁格 → 逐格放大 → 逐格圖生視頻。提格咒語：`Isolate image number [N] ... upscale it to a standalone shot.` 已擴到 25 宮格；Seedance 2.0 可整張宮格直餵（每格當 keyframe 插值）。
3. 「母图/母片」**不是社群通行術語**（對抗驗證：搜尋摘要會偽造用例，逐一 fetch 全數證偽）。通行語：九宫格分镜、三视图、角色资产、垫图。

**DreamF 現況對照：我們的「大圖分鏡表」是影格生完、按開拍後才拼的 QC 快照——人家的母片是源頭，我們的是收據。**

## 三、首尾幀的真實定位

- 首尾幀＝**轉場/精確落點工具**（變身、產品揭示、必須落在特定畫面的動作），不是全片骨幹。
- 多鏡影片預設＝**每鏡從參考資產獨立重生**；一致性靠「參考圖＋逐字重複的 style block＋固定角色關鍵詞」三層保險。
- 串接（尾幀接首幀）公認劣化：剎車感（即夢官方自認）、色偏累積、接縫凍結；對策＝接點落中性姿勢（≈我們的休止符律！）、每 ~2 次串接從新 keyframe 重啟、後期統一調色。
- 多 keyframe 插值是接替者：即夢智能多帧 2–10 帧→54s 一鏡到底；ComfyUI Wan2.2 多關鍵帧工作流。**DreamF 的 K+1 共用幀架構其實更接近這一支**（不是逐段 chain 影片輸出，而是先生全部靜幀再插值），方向不算錯，但影格從純文字生、只有 frame-0 風格錨＝身份鎖最弱的一版。

## 四、參考圖（ingredients/references）主力機制

| 模型 | 參考上限 | 備註 |
|---|---|---|
| Veo 3.1 | 3 張 asset images | 另有 first+last frame、extend（+7s×20 次至 148s）、timestamp prompting（單 8s 內切多鏡） |
| Runway Gen-4 | 影像 References 3 張＋@tag；影片只收 1 首幀 | 「References 定義角色是誰，prompt 定義發生什麼」 |
| Kling | 1.6 Elements 4 張；O1 reference-to-video 7 個 | |
| Vidu | 1–7 張 @subjectname | 7 主體各自保持 |
| Seedance 2.0 | 9 圖＋3 影片＋3 音訊 @素材名 | 現役最大 |
| Nano Banana Pro (gemini-3-pro-image) | 14 張（6 obj+5 char+3 style），5 人一致 | 我們現用 gemini-2.5-flash-image 也支援多圖參考 |

- Google 官方 Veo 3.1 處方：「用 Gemini Flash Image 分別生成角色/場景/物件參考圖 → 餵 Veo，prompt 寫 Using the provided images for [X], [Y], and [setting]…」
- 用參考圖時**不要在文字裡重述角色外觀**（衝突導致漂移）。
- 多角色同框＝已知難題（identity collision）；業界標準路徑＝**compose-then-animate**：先用影像模型合成含兩角色的 keyframe，再 i2v。

## 五、經濟學（成本結構的根據）

- 抽卡率分層：空鏡 1:3–1:5；一般 1:20–1:30；高難度上百抽。PJ Ace NBA 廣告 300–400 生成 → 15 採用（4–5%）。
- 行業計價：AI 短劇 ~1000 元/分鐘（2026 初）；個人毛成本 <300 元/分鐘；token 佔成本可達 70%。
- 工作室分工出現新工種「抽卡师」（命中 ~20%）。
- 教訓：把迭代留在影像層（便宜），影片層只買已核准的東西——與 DreamF 簽字閘理念同族，但我們缺「影像層迭代的房間」。

## 七、時效性警示

- Sora app 已關（2026-04）、API 2026-09 停用——storyboard UI 思想可參考，產品不可依賴。
- Google Flow 方向＝stills-first + asset-centric（資產是一等公民，影片是衍生物），2026-02 併入 Whisk/ImageFX。
- 市場結果偏向資產中心模式（Flow 存活壯大、Sora app 死亡）。
