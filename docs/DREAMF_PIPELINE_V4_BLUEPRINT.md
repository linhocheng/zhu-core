## 0. WHY（一段話）

V3 的八幕是「表單流水線」——每一幕都是填欄位、按按鈕。客戶要的是**跟人聊天，聊出一支片**。
今天（2026-08-05）把後臺編修改成對話式之後，Adam 的判斷是：對話不該只是編修的介面，
它就是整條產線本身。UDN 議題臺已經驗證了這個形狀（`[[DISPATCH]]` 標記讓角色一邊聊一邊
產出資產），DreamF 把它接管到影像領域。

**V3 沒有錯，是沒走完**：identity before frames 的內核（先鎖人景光、再下分鏡、母圖定構圖、
放大成真影格、最後才燒 Veo）全部保留。V4 換掉的是**人怎麼跟它互動**。

## 1. 新舊管線對照

```
V3（八幕表單）:
接案 → 面談 → 美術 → 分鏡 → 影格 → 拍攝 → 試片 → 交片
      ▲問答     ▲卡片    ▲表格   ▲母圖+放大  ▲Veo

V4（兩階段對話 + 三道閘）:
接案 → 【第一階段對話：設定】 → 【第二階段對話：劇本】 → 母片 → 單圖 → 縫合 → 交片
        導演×客戶聊              導演×客戶聊            ▲閘1   ▲閘2   ▲閘3
        產出 3-5 張參考圖         產出 6-8 張分鏡卡
```

## 2. 三個角色（Adam 2026-08-05 定義）

| 角色 | 本質 | 人設 | prompt 可改 | 數量 |
|---|---|---|---|---|
| **導演** | 主導對話、下判斷 | 有 | 是（獨立 prompt） | 一個或多個 |
| **攝影師** | 影像語言——生圖 prompt、運鏡、光線 | 有 | 是（獨立 prompt） | 一個或多個 |
| **製片** | 成本計算、閘門、預算 | **無** | — | 不是角色，是程式 |

**製片為什麼不是 LLM**：成本計算是確定性工作（天條）。現有 `guards.ts`＋`cost_ledger`＋
`computeContractUsd` 就是製片本體，V4 不動它，只是給它一個名字。**把算錢丟給 LLM 是天條違反。**

**導演與攝影師怎麼分工**：導演跟客戶說中文、談意圖與判斷；攝影師把它翻成英文生圖語言。
這正是今天做的「中文 desc / 英文 promptEn」分工，V4 把英文那一側交給一個**具名、可改 prompt
的專業角色**——不再是藏在 code 裡的匿名 system prompt。這也解釋了為什麼要兩個角色而不是一個：
那是兩種專業，不是同一個人的兩張嘴。

## 3. 第一階段對話：設定

導演跟客戶聊，聊出這支片的「人、物、景、光」，產出 **3-5 張參考圖**（張數看對話當下需要）：

| 類型 | 內容 | 張數 |
|---|---|---|
| 角色 | 有人物才有；正面 + 側面 | 核心角色可能 3-5 張 |
| 道具 | 關鍵物件 | 依需要 |
| 場景 | 環境圖（無人空景，跨鏡復用鐵律） | 依需要 |
| 色調 | 色調卡（＝STYLE BIBLE 的視覺化） | 1 |

- 導演在對話裡夾帶 `[[ASSET]]` 標記 → 後端確定性剝除 → 種資產卡（UDN `[[DISPATCH]]` 同款機制）
- 攝影師負責把導演的中文意圖翻成 promptEn（沿用今天做的 chat 原子同步：中英一起落庫，不分裂）
- 客戶逐張核准／打回／改（沿用今天做的對話式編修）
- **這一階段要很專業**——參考圖的版式（三視圖／多機位／色調卡）沿用 `prompts.ts` 既有模板

## 4. 第二階段對話：劇本腳本

設定完成後，第二輪對話——導演跟客戶聊劇本與腳本，產出 **6-8 張分鏡卡**：

- 每張卡＝一個鏡頭：演什麼、幾秒（4/6/8）、怎麼接上一段（延續／後期轉場／切換）
- 這些在對話裡談定，不是填表格（表格降為「看結果」的檢視面，仍可手動微調）
- **轉場在這裡就定死**——所以最後縫合階段只是確認，不是決策（Adam 明確指出）

## 5. 三道閘

| 閘 | 位置 | 放行什麼 | 錢的量級 |
|---|---|---|---|
| **閘1 母片** | 6-8 張卡定稿後，生一張母片（第二次生圖） | 放行「小圖放大成單圖」 | 母片 $0.25 |
| **閘2 單圖** | 單圖全部放大完成 | 放行「縫合成片」 | 單圖 6-8 × $0.25 ≈ $2 |
| **閘3 縫合** | 縫合前最後確認 | 放行 Veo | Veo 6-8 段 ≈ $2.4-6.4 |

**承重牆 #1 落在閘3**：Veo 是最貴的一層，錢閘守在它前面（原則不變，位置從「簽字」搬到「縫合確認」）。
閘1 沿用現有承重牆 #7（母圖閘）的邏輯：**貴的那層動工前，便宜那層要先有人點頭**。

## 6. 保留 vs 重寫

**保留（資產不是包袱）**：
- 引擎層：`gpt-image.ts` / `vertex.ts` / `grid.ts` / `storage.ts` / `bridge.ts` / `contact-sheet.ts`
- 地基：門禁、資料憲法、Jobs+lease+watchdog、cost_ledger、部署管線、CI
- 承重牆內核：程式驗證 LLM 輸出、表存描述圖存指紋、母圖閘、秒數格律、錢閘
- 今天做的對話式編修（V4 直接把它擴大成主幹）

**重寫**：
- 幕次流程與狀態機（八幕 → 兩階段＋三閘）
- CaseRoom UI（表單流水線 → 對話為主體）
- 導演/攝影師從 code 常數搬進 DB（可改 prompt 的具名角色）

**刪除（Adam 2026-08-05 授權）**：
- 所有既有案子 + GCS 影片檔與資產檔全刪
- V1/V2/V3 相容分支（`arting` 遺留態、legacy 無母圖分支、舊案 8 秒推導）——沒有舊資料就不需要相容層
