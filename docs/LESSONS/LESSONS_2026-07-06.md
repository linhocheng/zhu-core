# LESSONS 2026-07-06 · v16 語音迭代＋文字過濾器同步＋殭屍常駐大清洗

## L1：「頓」有兩種病——CPU 飽和與 event-loop 堵塞，鑑別信號不同
- 現象：v15.3.1 用 cpu=2 收案後，v16 撥測「說再見時卡頓」。log 對時發現 `slower than realtime` 與 `Memory saved` 同一毫秒出現、道別段三連寫——不是 CPU 不夠，是 `remember` 工具裸同步呼叫 `write_memory`（Vertex embedding HTTP＋50 條 dedup＋Firestore 寫入 0.5-2s）踩在 event loop 上。
- 根因：GIL 下 event loop 只有一條線，同步 HTTP 一堵，TTS 抽不動、VAD 排隊——給八顆核也一樣卡。
- 下次：見「頓」先分型——**持續性**速率不足（TTS KB/s 長期 < 播放率）＝CPU 飽和，加硬體；**尖峰式**卡頓且與某事件精準同框＝event-loop 堵塞，找裸同步呼叫下放 to_thread。
- 對應 feedback：ambiguous-signal 家族——兩種頓的表面症狀相同，鑑別靠信號形狀不靠體感。

## L2：紀律有時間差——新碼守新規，存量代碼沒人回頭掃
- 現象：同一檔案裡 v15 新寫的 `_dynamic_recall` 乖乖 `asyncio.to_thread`，更早期的 `remember_tool`/`dispatch_*` 全是裸同步——「off-path 一律下放 thread」的紀律立起來後，只約束了新增的行。
- 根因：立紀律當下沒有回溯掃描存量。
- 下次：立新紀律的同一個 commit，grep 全檔找同型舊雷一次掃掉。
- 對應 feedback：defend-at-convergence-point 的時間軸版——收斂點不只在空間（咽喉），也在時間（立法當下回溯）。

## L3：版本繁殖會複製舊雷——修過的病跟著沒修過的基因一起複製
- 現象：3a 殭屍 timer（掛斷後對空房評估、每次燒一通 LLM call）在 v6/v8/v9/v10 就修過同型雷，v15/v16 血統裡又活著。
- 根因：版本用「複製前一版」繁殖，歷代修法沒有沉澱進共用模組、也沒有開新版 checklist。
- 下次：修 lifecycle/資源類的雷，修完問一句「這修法在不在會被複製的檔案裡」；不在就要嘛搬進共用模組，要嘛進開新版 checklist。
- 對應 feedback：self-rescheduling-loop-needs-lifecycle-stop（同一條雷第五次出現，這次連根拔）。

## L4：版本隔離紀律缺了「退役」這一步——16 台殭屍常駐燒 $963/月
- 現象：ailivex base~v15 共 14 台語音服務全部 min-instances=1 + no-throttling 常駐計費（$800+/月），加 jiangbin、ailive 兩台共 ~$963/月 ≈ NT$30 萬/年，燒了數月沒人看見。
- 根因：版本隔離紀律有「開新版不動舊版」，沒有「新版收案時舊版降常駐」——每開一版多養一台殭屍。
- 下次：**vN 收案當天，v(N-1) `--min-instances=0`**。降 0 不是刪：env/image 全留，一條命令一分鐘熱回。另一半知識：**LiveKit agent 降 0＝聾不是慢**（agent 是主動連 LiveKit 領工，沒 HTTP 請求會喚醒它），所以降 0 等於功能下線，只適用「沒人會再打」的版本。
- 對應 feedback：新刻 [[skill_cloudrun_version_retirement]]。

## L5：破音字用「借同音字」定音，抓/放雙向測試才算詞條成立
- 現象：MiniMax 把「混淆」唸 xiáo（台灣唸 yáo）、「劃(huà)」經 opencc 變「划」被唸 huá。
- 修法：確定性替換借音——混淆→混摇、划一划→画一画、`划(?=[^，。！？]{0,4}线)`→画（「计划路线」誤中變「计画」讀音仍對＝無害誤中）。每條規則配「不該誤殺」對照（划算/划船），雙向過才進表。
- 下次：破音字彙報進來，先想「借哪個同音字」＋「哪些正常詞會被誤殺」，規則作用在簡體層（opencc 之後）。
- 對應 feedback：filter-unit-matches-error-shape（同族方法論，單位是「詞+語境」不是字）。

## L6：長任務不配磚頭——Jobs 取代 min=1 常駐 worker（天條升級）
- 現象：三台 min=1 worker 每月 ~$220 保護費；降 0 後長生成（20-45 分）被 15 分鐘閒置回收砍死
- 根因：舊天條（no-throttle+min=1）是躲 throttling 的代價解；Cloud Run Jobs 同時解 throttle/回收/常駐費三件事
- 下次：判準一句話「閒著時有沒有人下一秒需要它」；podcast 兩平台已搬 Jobs 真實驗收全通
- 對應 feedback：standing-cost-only-for-instant-readiness（新刻）

## L7：設定/實例/計費三面分離——「複核全過」查錯面＝零資訊
- 現象：前日「16 台降 0 複核全過」漏一台（流量釘 5/23 舊 revision，min 跟 serving revision 走）；語音開關「關了還接通」三度誤判
- 根因：複核對象是 annotation 不是計費錶；中間還隔著部署驗證實例（每次設定變更生一顆活 15 分）＋graceful drain（通話撐實例不死）
- 下次：驗錢一律 billable_instance_time/instance_count 歸零；掃 status.traffic vs latestReadyRevision
- 對應 feedback：cost-verify-billing-meter-not-config（新刻，ambiguous_signal 的費用版）

## L8：部署腳本是殭屍復活術——刻完天條一小時自己踩
- 現象：修了兩個 podcast-worker cloudbuild 的 min=1，部署破音字時 v16 的 cloudbuild 把 Adam 關掉的語音無聲重開
- 根因：刻天條時掃描範圍=「手上正在改的檔案」不是「全部 cloudbuild」；grep 全域才是掃
- 下次：手動改雲端資源後 `grep -rn "min-instances" **/cloudbuild*.yaml` 全掃；語音類服務的 min-instances 不寫進 deploy 腳本（省略=保留現值），主人只有後台開關
- 對應 feedback：manual-cloud-change-sync-deploy-script（新刻當天自踩自抓）

## L9：查不到 ≠ 不存在
- 現象：Budget API 沒開 → list 失敗 → 對 Adam 斷言「預算警報一個都沒設」；開 API 後發現本來就有兩條 TWD 3000
- 根因：把「查詢失敗」當「查詢結果為空」
- 下次：API 錯誤/權限錯誤時只能說「查不到」，不能說「沒有」
- 對應 feedback：ambiguous_signal_not_proof（同族：錯誤訊號被解讀成否定事實）
