# LESSONS 2026-07-24 · UDN Drive 鏡像素材館一日上線＋被真實使用炸出 OOM 當日根治；王彩雲貼文圖打包

### L1：使用者輸入管線第一版就串流；測試尺度要問需求不問樣本
現象：54MB 影片測綠，宣告完成三小時後真實使用者丟 181MB → buffer 整檔進 RAM → Cloud Run 1Gi OOM 連環炸，使用者端看到天書錯誤。
根因：`arrayBuffer()` 接上傳＝記憶體隨檔案大小線性成長；測試樣本的尺度是「手邊剛好有什麼」不是「需求允許多大」。
下次：看到「使用者會丟任意檔案」的需求，設計時先問極端形狀（最大檔/最深巢狀），傳輸一律串流直通；前端 fetch 一律 text→try JSON（infra 層錯誤是純文字）。
對應 feedback：[[skill_user_upload_pipeline_pitfalls]]（四雷全記）。

### L2：部署收案看行為不看宣告——allow-unauthenticated 與 IAM 404 假象
現象：cloudbuild 帶 `--allow-unauthenticated` deploy SUCCESS，頁面卻 403；iamcredentials 剛 grant 完打出 404 讓我以為 URL 拼錯。
根因：Cloud Run 公開存取要顯式 allUsers invoker binding，deploy flag 不保證；iamcredentials 對無權限 caller 回 404（掩蓋 SA 存在性），propagation 期間的 404 長得跟路徑錯誤一模一樣。
下次：部署收案＝curl 200；剛 grant 的 IAM 打到 404 先等 30-60s 重試再查 URL。
對應 feedback：[[feedback_ambiguous_signal_not_proof]]（部署版）。

### L1：debug 直撈 DB 的結果不能當 UI 行為回報
- 現象：raw Firestore query 列出四位角色（含 archived 的 Alex），回報 Adam「四個聲音都能選」；實際 UI 走 getCharacters() 過濾後只有三位，Adam 誤以為系統有 bug
- 根因：查詢層級錯位——原始層看得到的，業務層不一定放行；回報對象是「UI 會顯示什麼」時必須走同一條讀路徑
- 下次：回報用戶可見行為前，打產品 API（或聲明「這是原始層資料，UI 可能過濾」）；debug script 輸出自帶層級標籤
- 對應 feedback：diagnosis_verify_before_write／memory_can_lie 家族新成員
