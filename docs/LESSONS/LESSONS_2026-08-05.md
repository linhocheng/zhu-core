### L1：核心架構重寫時，deploy 前的「唯讀模擬驗證」不能取代「真實觸發一次」
- 現象：本地跑 dailyPromptSlice 對真實 promptId 算出正確切片，一度以為這樣就夠了才敢報告 Adam；後來 Adam 說「繼續」才真的觸發 Cloud Run Job，結果 gcloud 回報「killed」——若沒有再去查執行紀錄+Firestore，這個模稜兩可的信號可能被誤判
- 根因：唯讀模擬只驗證了「純函數邏輯對不對」，沒驗證「Firestore 寫入權限、job 四件套、vacantStreak 更新時機」這些只有真實跑過一次才會暴露的整合面
- 下次：核心管線重寫，deploy 後一定要真實觸發一次完整流程（哪怕小成本），唯讀模擬只能當前置檢查，不能當最終驗證
- 對應天條：feedback_ambiguous_signal_not_proof
