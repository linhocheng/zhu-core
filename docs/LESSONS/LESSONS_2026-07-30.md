# LESSONS 2026-07-30 · 排隊二事收案(帳號大小寫+記憶審核台)＋talk 琉璃話機雙版型＋INLY 換裝新設計

### L1:二進位資產不能靠 LLM 轉錄——位元組要走程式管道
- 現象:design 專案 logo PNG 經 get_file(base64 進 context)→Write 落地,file/sips 讀 header 全過,瀏覽器渲染失敗、API 拒收=資料段損毀
- 根因:11KB base64 靠模型逐字重現,錯一個字元=整檔報廢;header 檢查(file/sips -g)只讀前幾十 bytes,是「設定面」不是「產物面」
- 下次:①二進位資產優先讓工具直寫磁碟(subagent 有同工具時派單)②沒有直寫管道就做 UI fallback+留補檔路徑 ③驗證用「完整解碼」(瀏覽器真渲染/PIL verify),不用 header 探針
- 對應 feedback:ambiguous_signal_not_proof(header 完好=模稜兩可信號)、deterministic_work_belongs_in_code(位元組搬運是計算不是判斷)

### L1：換資料來源比旁加更能根治——D10 的真解在 hidden JSON 不在 DOM
- 現象：留言數 D10 抓不到（DOM aria-label 走訪回 0），一度想「另外補一個抓留言數的方法」
- 根因：DOM aria-label 走訪本來就脆；Threads 頁面內嵌 JSON（thread_items）裡 direct_reply_count 是乾淨數字，四數全在。旁加一個抓法＝在脆弱上疊補丁；換來源＝根治且順手把留言清單一起拿到
- 下次：抓取類「某欄位抓不到」先問「有沒有更結構化的同源」（hidden JSON / API 回應）再決定補還是換；換來源常一石多鳥
- 對應 feedback：deterministic_work_belongs_in_code（結構化 JSON 比 DOM 走訪確定）＋solve_root_not_symptom
### L2：規劃期的價值是校準模型，不是產出 code——手癢要按住
- 現象：純聊天階段兩次想直接動手（/connect 警語、驗 ASN 順手改 config）
- 根因：工程師反射把「聊到一個明確可做的點」當成「該做了」；但 Adam 要的是先把「為誰做、怎麼用」想清楚，過早動手會蓋錯版本（見 delta：SaaS 假想敵作廢）
- 下次：Adam 說「純聊天/先想」時，明確可做的點記進 memory 待辦，不動手；規劃期用「問對問題」使力不用「產出」使力
- 對應 feedback：clarify_before_execute（沒說動手就不動手）＋display_impulse（想證明自己會蓋＝展示衝動）
