# LESSONS 2026-07-20 · UDN＋ailiveX 接資安掃描四件套 CI（複製 geo 模板）——CI 一上線就照出既有存量債，triage 三路＋鑑別信號全程接住

### L1：接既有平台的資安 CI，先照出的是存量債——triage 是判斷活，分三路
現象：同一份 geo 模板，UDN 照出 1 個（worker Dockerfile root）、ailiveX 照出 5 個（3 Dockerfile root＋2 npm high）。都是既有問題，非我新引入。
根因：新平台（geo 剛蓋、我控制全部）沒存量債；成熟平台累積了未接 CI 期間的債，掃描器一上線全曝光。
下次：接既有平台 CI 前先本地預跑一輪看存量債規模；triage 三路——①安全可修（node worker USER）修源碼＋build 驗；②碰 live 服務/撞平行 session（Python 共用 image、v20 package.json）記債＋inline nosemgrep 不擅改；③要降 gate 標準顯式＋CI 可見（continue-on-error 讓 finding 浮 annotation）＋記債＋觸發條件。三路都不靜默。
對應 feedback：feedback_surface_technical_debt＋pinning test 變紅＝正常運作。

### L2：Dockerfile 的 nosemgrep 要放 CMD 前一行（不能 inline），且必須重掃驗證
現象：Docker 不支援 CMD 行尾 inline 註解（會被當指令一部分），所以 nosemgrep 只能放前一行。
根因：semgrep 支援「同行或前一行」的 nosemgrep；Dockerfile 只能用前一行。
下次：放前一行後**必重掃確認 finding 真的消失**（本場重掃 0 findings 才確認生效），不假設語法對就生效——鑑別信號的 nosemgrep 版。
對應 feedback：feedback_flagged_risk_must_be_verified。
