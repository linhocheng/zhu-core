# LESSONS 2026-07-21 · 三站 CSP nonce 化——同模板複製 UDN/geo/ailiveX，每站雷不同逐站真瀏覽器驗，全部署 production 驗綠

### L1：同模板複製到多站，每站都要逐站真瀏覽器測——模板過一站不等於全過
現象：同一份 CSP nonce 模板，geo 一次過、UDN 撞 Next 16 靜態頁死白頁（0/15 nonce）、ailiveX 撞外部 Google Fonts 被 style-src 擋。三站三種不同破法。
根因：模板消滅共通結構，但每站的框架版本／字型載法／靜態頁分布／既有 middleware 各不同——這些差異正是模板沒覆蓋、會咬人的地方。
下次：複製前端加固模板到多站，逐站跑真瀏覽器測（playwright headless），收三信號：script nonce 覆蓋 N/N、0 CSP violation、client 軟導航（window 未重載＝真 hydrate，比 __next_f 可靠）。心裡冒出「一樣的改法應該都會過」就是要逐站真測的訊號。
對應 feedback：[[feedback_flagged_risk_must_be_verified]]＋[[skill_csp_nonce_per_site_headless_verify]]。

### L2：Next 16 三個破壞性雷（升級/加固 Next 平台前必知）
現象：middleware.ts 在 16.2 改名 proxy.ts（16.1 仍認 middleware.ts）；靜態頁 nonce 對不上→strict-dynamic 全擋死白頁；`window.__next_f.length` hydrate 後被清空、不是有效探針。
根因：Next 16 一系列 breaking changes（AGENTS.md 開頭就警告「This is NOT the Next.js you know」）。
下次：動 Next 16 前先核版本＋讀 `node_modules/next/dist/docs/`；nonce 必配 root layout force-dynamic；hydration 驗證用軟導航不用 __next_f。
對應 feedback：[[reference_nextjs16_csp_nonce]]（完整技術細節）。

### L1：功能規劃先聲明出發點（成效/管理/程式方便），說不出口就還沒想清楚
- 現象：排程規劃自以為在解「分散負載」，Adam 三問後發現實際是管理導向（後台可調），分散/避峰根本沒解到（day-of-month ≠ time-of-day；手動可調 ≠ 自動攤平）
- 根因：從「能做什麼功能」起手而不是從「要解什麼問題」起手；把附帶價值當主目標敘事
- 下次：規劃書第一行寫出發點三選一＋為什麼；每個設計決策對照出發點檢驗（「這條在服務成效還是管理？」）
- 對應 feedback：solve-root-not-symptom（規劃版）
### L2：symlink 共用檔雙雷——Dockerfile 逐檔 COPY 清單＋相對 import 以 symlink 位置解析
- 現象：①findings.ts 本機 build 綠、Docker build 炸 Module not found（Dockerfile.admin 逐檔 COPY 只搬了 collections.ts）②schedule.ts 內 `./types.js` 相對 import 在 admin 端解析失敗（TS 以 symlink 所在目錄解析，非 realpath）
- 根因：symlink 單一真相源模式的隱含契約：消費端 build context 要能重建同樣的相對拓樸
- 下次：加新 src 共用檔＝三件套同步：src 檔＋admin symlink＋Dockerfile COPY；共用檔若有相對 import，被 import 的檔也要進 symlink 鏈；Dockerfile 檔頭已加註
- 對應 feedback：manual-cloud-change-sync-deploy-script 家族（部署腳本是未來的現場——COPY 清單也是）

### L1：容量常數會過期——成長事件（加引擎/加租戶/cron 合併）必須回頭重驗
- 現象：60 分 task-timeout 是單租戶四引擎時代定的；加 AIO、租戶 1→3、cron 合併單執行串行後沒人回驗 → 並行日雙撞死，且下週一 cron 必爆（104 分 > 60 分）
- 根因：常數當設定不當斷言——沒把「推導前提」寫在旁邊，前提變了無人知
- 下次：定容量常數必附推導式註解；成長事件 checklist 掃所有數字常數問「前提還成立嗎」；串行合併用當日總和算
- 對應 feedback：feedback-capacity-constants-expire（本場新鑄）
### L2：失敗路徑也要記帳——cost 隨心跳寫回，SIGKILL 不走 catch
- 現象：兩輪超時燒 ~$5.43、job 帳 $0.00；預算閘讀 job cost＝對失敗風暴全盲
- 根因：記帳只掛在成功結尾；timeout 殺進程不執行 catch，事後補帳救不了這種死法
- 下次：長任務 cost 隨心跳增量寫回（同筆 doc update 零成本）；catch 同步補帳；稽核成本用原始事件層重算對帳
- 對應 feedback：skill-cost-on-heartbeat-failure-accounting（本場新鑄，billing-meter 天條家族）
### L3：本機接力正姿——nohup 脫鉤＋persistent Monitor 盯 log＋腳本冪等
- 現象：harness 追蹤的背景接力連兩次在等待階段被砍（輸出停在 watching 行）
- 根因：tracked 背景任務有 harness 生命週期管理，長駐等待活不過幾分鐘
- 下次：`nohup node x.mjs >> log &` 脫鉤＋Monitor tail-grep 事件回報（filter 必含失敗信號）；腳本必冪等可重跑；正式路徑不依賴本機
- 對應 feedback：skill-detached-relay-nohup-monitor（本場新鑄）
### L4：快照型報告要聲明資料依賴順序——健檢在監測前跑＝④ 空
- 現象：Adam 看 INLY 健檢沒有第四區，以為 bug；實為健檢快照生成時監測還沒跑
- 根因：快照沒把「依賴的上游資料存在與否」顯式化，空區塊直接不渲染＝用戶無從分辨「沒做」和「還沒有料」
- 下次：依賴上游的報告區塊，上游缺席時渲染「要先跑 X 才有這區」的占位說明，不要無聲消失
- 對應 feedback：feedback-interface-blood-vessel-check（血管接通了嗎的顯示版）
