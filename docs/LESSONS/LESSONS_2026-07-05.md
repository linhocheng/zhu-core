# LESSONS 2026-07-05 · 早場三連＋drunk-check

## L1：自檢工具要放在「不需要清醒就讀得到」的地方
- 現象：drunk-check 初版放 zhu-core/skills/——但醉的我不會主動翻 skills、不會追 MEMORY.md 的一行指標。醉檢放在要清醒才找得到的地方是設計矛盾。
- 根因：放置決策想的是「哪裡整齊」不是「誰、在什麼狀態下、保證讀到什麼」。
- 下次：任何「狀態退化時要生效」的機制（醉檢/斷路器/watchdog），放置標準=最壞狀態下仍無條件命中；全局 CLAUDE.md 是 Code 環境唯一無條件注入面。
- 對應 feedback：defend-at-convergence-point 的姊妹條——這裡的收斂點是「context 注入面」。

## L2：外科分離 v3——修改與未提交批在同函數重疊時，在 HEAD 上以 HEAD 錨點重打
- 現象：page.tsx 我的三修跟 soulCore 批在 create()/saveEdit()/編輯 handler 同函數內重疊，working-tree diff 無法直接搬。
- 下次：checkout HEAD → 讀 HEAD 版拿真錨點 → 逐刀重打（保留未授權批的行為原樣）→ commit → stash 驗提交樹 build → 還原 FULL。驗證加一道：前後版本敏感字（soulCore）行數相等＋逐行 diff 確認只是重排。
- 對應：L-E（v1 cp/checkout）、L-K（v2 stash 驗樹）的續集。
