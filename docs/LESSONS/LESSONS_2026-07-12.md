# LESSONS 2026-07-12 · podcast 關係矩陣＋無形製作人上線，Adam 首次坐上導播台

### L1：驗收量尺要有「token 衛生」這一類
現象：`</s>` 字面洩漏進台詞結尾，協議/風格/內容三層驗證全部沒攔。
根因：量尺只驗「說了什麼」，沒驗「輸出載體乾不乾淨」——EOS/特殊標記是一整類沒設防的雜訊。
下次：任何 LLM 輸出出口都過 stripModelTokens 這類確定性清洗；建新管線時把「token 衛生」放進驗收清單。
對應 feedback：deterministic-work-belongs-in-code（不寫 prompt 拜託模型別輸出，程式剝）。

### L2：新形狀的資料要重走所有舊消費端
現象：duo 台詞是多段落，音檔 tagging 的行編號往返只抓第一行、前端 parseScript 丟續段——兩處舊消費端都假設單行，段落無聲蒸發。
根因：生產端升級（多段落）後只驗了新管線本身，沒回頭掃「誰在吃這個資料」的存量消費端。
下次：改變資料形狀時 grep 所有讀取方，逐個過一遍新形狀；「從沒完整走過」的路徑＝未驗證路徑。
對應 feedback：backend-client-must-sync 的資料形狀版。

### L3：拿掉劇場，留下方向感
現象：「台下坐著的人」讓所有開放議題被壓成救人題，角色對幽靈喊話，REFOCUS 連踩。
根因：把「這集為誰做」（方向感）和「有個人在現場」（劇場）綁在一起裝進去了——前者是藥，後者是戲。
下次：給系統加「對象感」時分兩層——思考層放羅盤（衡量用），表達層不引入不存在的實體；留空要是合法狀態，不硬生成。
對應 feedback：filter-unit-matches-error-shape 家族（第一反應加實體＝新的封詞）。

### L4：剪接權要結構化，不要事後驗證
現象：收斂台初版讓製作人吐「刪後全文」再程式驗證是否純刪除——輸出大、慢、還要防越權。
根因：把「選擇」和「書寫」混在同一個輸出裡。
下次：凡「只能選不能寫」的權限，介面就設計成只能回編號/ID——越權在結構上不可能，順帶輸出縮百倍。
對應 feedback：deterministic-work-belongs-in-code＋defend-at-convergence-point。
