# LESSONS 2026-07-19 · 共創系統一日全迴圈——admin 教角色→角色提案→審核轉正→v20 全用戶遞招上線

### L1：跨線斷言先 grep 再開口
- 現象：對 Adam 說「文字線和語音線都會吃遞招」，數小時後被「他說沒有」翻案——語音 agent 全文無 knowledge/methodology 字樣
- 根因：從「資料模型共用」推論「消費端共用」——管道存在性是每線獨立的事實，架構相似性不是證據
- 下次：說「X 線也會 Y」之前，grep X 線的消費端代碼；一分鐘的 grep 換一個不用認錯的斷言
- 對應 feedback：sandtable_not_validation（跨線版）

### L2：git add -A 是平行施工的散彈槍
- 現象：收 git 時 add -A 把平行 session 的 FOUNDATION.md/tests/next.config CSP 一併收進 commit 並推出
- 根因：status 印了、眼睛掃過、手沒停——「反正這 repo 都是我的改動」的過期假設（早上為真，晚上已不真）
- 下次：多 session 共用 repo 一律顯式 git add <路徑清單>，不用 -A；status 裡有一個認不出的檔名就全停
- 對應 feedback：parallel_sessions_same_repo（首次實戰踩雷）；修法=v18.17.1 退回外來檔還原未提交狀態

### L3：背景注入系統要在設計時就配冷卻
- 現象：方法論 exit 後同套下一輪立刻再遞（話題還在線上，每輪重匹配）
- 根因：觸發匹配是無狀態的，但「剛被收掉」是狀態——退出即事件，事件要留痕影響後續匹配
- 下次：任何「條件滿足→注入」的迴圈，設計時自問「剛拒絕/退出過的東西多久內不該再來」；本次補 METHOD_REOFFER_COOLDOWN=120s

### L1：接 CI 的 workflow 檔會被自己的 SAST 掃到——先掃後寫等於漏掉自己
現象：本地 semgrep 預跑 75 檔 0 findings，push 後 CI 76 檔抓到 5 findings，全指向剛推的 workflow 檔自己（unpinned action）。
根因：我「先本地預跑掃描、後寫 workflow」，本地掃的時候 workflow 還不存在——本地檔案集少一個。CI clean checkout 掃到 workflow 自己。
下次：寫完 workflow 後，本地要在「workflow 檔已存在」的狀態重跑一次 SAST（跟 CI 同檔案集）再 push；接 CI 時假設「掃描器會掃到自己」，workflow 的 actions 直接 pin SHA。
對應 feedback：本機通≠CI通（BUILDING_PROTOCOL）的檔案集變體。

### L2：新 SAST 上線第一秒抓到的問題可能在它自己身上——那是正常運作不是誤報
現象：Semgrep 首跑就紅，findings 全在 CI workflow 檔（供應鏈規則：action 該 pin SHA 不用可變 tag）。
根因：unpinned action（@v4 tag 可被重指向惡意 commit）是真供應鏈風險，Semgrep 判對了。
下次：新警報線抓到自己時，先問「它說得對嗎」而非「怎麼讓它閉嘴」；對的就修（pin SHA），不對才 ignore。關規則＝剪警報線。
對應 feedback：pinning test 變紅＝系統正常運作（holygrail2 收編當天實踐）。

### L1：協作者的請求先驗前提，再動手
- 現象：WAITIN 請求「A1 補 openai/perplexity key」附成本試算；三面驗證發現四引擎開關全開、key 全有效、真實 runs 四引擎各 60+ 筆 ok——任務不存在
- 根因：把協作者的現況描述當事實輸入；他的認知停在舊版預設（雙引擎），沒人驗
- 下次：任何「幫我開/修/補 X」先驗 X 的現況（設定面+憑證面+計費面），回覆「本來就開著」比「開好了」誠實且省一次誤操作
- 對應 feedback：feedback_memory_can_lie（外延：別人的記憶也會說謊）
