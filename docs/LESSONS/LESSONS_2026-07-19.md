# LESSONS 2026-07-19 · 共創系統一日全迴圈——admin 教角色→角色提案→審核轉正→v20 全用戶遞招上線

### L1：跨線斷言先 grep 再開口
- 現象：對 Adam 說「文字線和語音線都會吃遞招」，數小時後被「他說沒有」翻案——語音 agent 全文無 knowledge/methodology 字樣
- 根因：從「資料模型共用」推論「消費端共用」——管道存在性是每線獨立的事實，架構相似性不是證據
- 下次：說「X 線也會 Y」之前，grep X 線的消費端代碼；一分鐘的 grep 換一個不用認錯的斷言
- 對應 feedback：sandtable_not_validation（跨線版）

### L2：git add -A 是平行施工的散彈槍
- 現象：收 git 時 add -A 把平行 session 的 FOUNDATION.md/tests/next.config CSP 一併收進 commit 並推出
- 根因：status 印了、眼睛掃過、手沒停——「反正這 repo 都是我的改動」的過期假設（早上為真，晚上已不真）
- 下次：多 session 共用 repo 一律顯式 git add <路徑清單>，不用 -A；status 裡有一個認不出的檔名就全停
- 對應 feedback：parallel_sessions_same_repo（首次實戰踩雷）；修法=v18.17.1 退回外來檔還原未提交狀態

### L3：背景注入系統要在設計時就配冷卻
- 現象：方法論 exit 後同套下一輪立刻再遞（話題還在線上，每輪重匹配）
- 根因：觸發匹配是無狀態的，但「剛被收掉」是狀態——退出即事件，事件要留痕影響後續匹配
- 下次：任何「條件滿足→注入」的迴圈，設計時自問「剛拒絕/退出過的東西多久內不該再來」；本次補 METHOD_REOFFER_COOLDOWN=120s
