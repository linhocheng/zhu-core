# LESSONS 2026-07-10 · Tracy 方法論規模化＋對外知識輸出

## L1：觸發 desc 的「磁鐵效應」只在規模化時現形
- 現象：5 套全綠的 triggerDesc，到 10 套時一套帶泛用語的 desc 一口氣搶走同批三題；15 套時又冒出詞級撞詞（「想提離職」vs「怕他離職」，embedding 分不出主詞）
- 根因：窄域語料 cosine 坍縮——所有 desc 都在講「人的困境」，泛用語成為公共引力；單批驗證通過 ≠ 併池後還對
- 下次：每批入庫後全量回歸是鐵律；desc 迭代方向永遠是「鎖獨有簽名」不是「加場景詞」；margin < 0.02 進觀察名單。已刻 memory（skill_methodology_trigger_scale）＋ skill 檔規模化章節
- 對應 feedback：sandtable_not_validation（單套驗過就以為批量也對＝沙推）

## L2：角色會把「自己的」工具講歪——soul 咬合 ≠ 材料忠實
- 現象：Tracy 四批共創中把 CALM/TRACK/HTMM/4S/3P/KISS 全部重新定義過，動作都好、標籤全歪；孫武沒這問題（材料是他的原著）
- 根因：角色的 soul 從材料萃取而來，但生成時是「用人格演工具」不是「查表引用工具」——人格越強、演得越自由
- 下次：共創產出過 schema 時固定跑「工具名校準」：動作保留、錯標籤拔掉、對照原始材料掃一遍。這一步已寫進對外 runbook 和 cocreate skill
- 對應 feedback：memory_can_lie 的變體——角色的「記憶」也會說謊，越自信越要對原文

## L3：對外知識輸出的三層架構（白皮書/runbook/參考值）比單檔好用
- 現象：朋友工程部要的東西從「字庫」一路長到「整套架構」；單一大檔會混掉「為什麼」和「怎麼做」
- 根因：AI 讀者的執行需求分兩態——建骨架時要原理，動手時要 checklist；混在一起兩邊都難用
- 下次：對外輸出固定拆三層：白皮書（架構＋設計決策）、runbook（step-by-step＋失敗速查表）、參考值表（標明「換模型必重校準」）；〔實戰〕〔建議〕標記不可省——零推測混充
- 對應 feedback：technical_honesty_over_smoothness（未實戰的設計標成建議，不為文件完整感而混充）

## L4：框架互操作層——單元測試測的是「自己想像中的框架」
- 現象：v18 優雅讓位 16 個單元測試全綠，四通真實通話每通撞一個新 bug（時鐘跨段污染/狀態重置誤翻案/暫停默殺黑洞/459ms 遲到 resume）
- 根因：測試向量是「我以為框架會怎麼呼叫 pause/resume/clear」，框架真實有三條 commit 路徑、六個呼叫點、時序從 74µs 到 5s 都有；驗證了自洽，沒驗證前提
- 下次：包任何框架的生命週期介面（audio output/lifecycle hooks）前，先窮舉框架源碼所有呼叫點＋抽真實 log 事件序列當測資，做「任意交錯順序」的 property-based 沙推，鐵律不變式（不掛死/不復播/不阻塞）全過才上線
- 對應 feedback：sandtable_not_validation（沙推不是驗證的第四張臉：測了，但測的是自己想像的對手）

## L5：時間差護欄兩個樣本就定閾值＝賭博
- 現象：用 0.25s 區分框架兩種 resume（樣本：74µs vs 3.2s，差四個數量級「很安全」）；第三個樣本 459ms 直接打臉
- 根因：狀態重置 resume 會先 await 生成收尾才發，延遲取決於生成狀態——是分佈不是定值
- 下次：分辨信號優先用「語意/狀態」不用「時間」；本案正解＝commit 後 resume 一律不翻案（clear 到達＝回合已定案，是狀態鐵律不是時間猜測）
- 對應 feedback：deterministic_work_belongs_in_code（確定性判斷要建立在不變式上，不是統計巧合上）

## L6：拿 Adam 的真通話當 QA 循環＝方法錯誤
- 現象：一晚五次部署、四通測試電話，每通都讓 Adam 撞一個新 bug，測到他說「先停在這裡，感覺 v18 被改亂了」
- 根因：離線可模擬的東西（框架事件交錯）沒先模擬，把發現成本轉嫁給用戶的真實體驗；「架構不亂」不等於「過程不亂」
- 下次：真人測試是驗收不是探索。探索用離線 harness；真人只驗「離線全綠之後」的版本，一次
- 對應 feedback：display_impulse 的變體——急著讓 Adam 看到「動起來」，每修一版就想立刻請他驗

## L4：真雙屬近鄰的 desc 修到 margin 歸零就該停
- 現象：換頻對話法（對爸媽溝通）入庫後搶走情緒勒索破解的球（「我媽每次一說我養你這麼大⋯」）；四輪 desc 手術每輪只挪 ~0.008，最終 margin 0.001 才翻正
- 根因：該測試句語義上就同時屬於兩域——「跟媽媽講話讓我痛苦」對兩套都是真的，embedding 分不動；這不是 desc 沒寫好，是觸發層的物理極限
- 下次：同錨定詞、兩域都合法的近鄰對，修到 margin 貼零就停手，剩下交給 preconditions 分流（遞招≠出招是第二層防線，實測成立）；不要為單句測試把 desc 削到失真
- 對應 feedback：solve_root_not_symptom——root 在語義雙屬，認清 root 無法在這層解，停手本身就是解

## L5：「該專業就專業、該自然就自然」是修不修的裁決線（Adam 定）
- 現象：沙盤抓到三個缺口——走步保守／八法只列 5/8／視覺換框定義漂移。Adam 裁定：節奏是自然可留，知識定義與覆蓋是專業必修
- 根因：頂 K 檢索對「切成多塊的清單/定義類小文件」天生殘缺（TOP_K=3 vs 八法 4 塊）；人格越強越會用自己的話重演定義
- 下次：修在咽喉 loadKnowledgeBlock 一處（小文件 ≤6 塊整份帶入＋定義保真指令），text/voice 全受益；分類新缺口時先問「這是專業還是自然」再決定動不動
- 對應 feedback：defend_at_convergence_point＋global_prompt_must_not_encode_personality（保真指令是格式紀律，不碰個性）

## L6：沙盤實測是設計驗收的最後一里
- 現象：親自下場當用戶才看到兩個設計的「活證據」：目標對頻器被誤遞但 Tracy 不接招（preconditions 安全網）、八法缺 3 法她說「不編出來騙你」（反幻覺紅線）——這些塊級驗證永遠測不出來
- 根因：塊級驗證測「管線給了什麼」，只有 LLM 級沙盤測「角色拿到之後怎麼用」；兩級測的是不同故障面
- 下次：知識庫/方法論類交付，塊級三件套之後固定加一輪唯讀沙盤（同款組裝、本地狀態機、不留痕）；抓到的缺口先分「專業/自然」再修
- 對應 feedback：interface_blood_vessel_check——血管接通了嗎的 LLM 級版本
