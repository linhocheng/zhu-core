# LESSONS 2026-08-07 · 心法動作化——把「自問」換成有產出物的動作，順帶撞出記憶檢索管道的靜默 bug

### L1：規則失效通常是文法問題，不是紀律問題

**現象**：8/6 我盤完 84 條心法、把 `feedback_ambiguous_signal_not_proof` 寫進報告，幾小時後違背它三次。同一天。
**根因**：那條規則的動詞是「先寫下一句話：修好了我會看到 X」——**一個只在我腦內發生、沒有產出物、沒有人檢查的動作**。壓力一來（急著收案、剛部署完自己的修法）它就蒸發，而且蒸發時不會有任何信號。對照組：`feedback_pipe_eats_exit_code` 二犯後改成鐵模板（「一律禁止接管子，只准這個形狀」），之後零犯。
**下次**：寫任何規範前先問**它的動詞是什麼**。「問自己 / 注意 / 記得 / 保持」→ 一定會失效，當場改寫。改寫的三個公式：**陽性對照**（信任「沒找到」前先餵已知樣本）、**產出物外置**（把答案寫進對話／交付訊息／commit）、**機器可偵測的觸發**（把「感覺到 X」換成「出現字串 Y」）。
**但書**：關係類的心法（沉默時回來找 Adam、技術誠實不讓路、用大白話問）**本來就是姿態，硬改成動作是假的**。今晚刻意留了 6 條沒動。
**對應 feedback**：`feedback_framework_vs_reflex` 的根因層；新增的動作化標記散在 12 條裡。

### L2：靜默壞掉的東西不會來找你，要主動去翻管道

**現象**：`parsers/memory.mjs:40` 的 `^(\w+):` 讀不進巢狀 frontmatter，**59 個記憶檔的 `type` 是 undefined** → tags 空、`lesson` 永遠 null。我天天在用 `zhu recall`，從來沒發現。
**根因**：這個 bug **沒有症狀**。檢索照樣回東西，只是回得比應該的差；`name: ""` 顯示成字面兩個引號，我看了無數次當成無關的顯示瑕疵。**降級不會報錯，只有比較才看得出來**——而我沒有比較對象。
**下次**：整理內容時**順手往下看一層管道**。今晚是因為在追「CLAUDE.md 和 memory 是兩份副本」才點開 parser 的。判準：**任何我每天在用、但從來沒讀過實作的東西，都是這種 bug 的溫床。**
**對應 feedback**：`feedback_silent_failure_absent_log`（靜默失敗用缺席的 log 診斷）的檢索版——這次連 log 都沒有，只有品質差異。

### L3：改了解析邏輯，快取會讓修法完全不生效且回報成功

**現象**：修完 parser 要重嵌，`zhu migrate` 用 **mtime cache** 判斷跳過——parser 改了但 187 個檔案的 mtime 沒變 → **全部 skip，然後印 `fail=0`**。
**根因**：快取的失效條件綁在**輸入**（檔案 mtime），但這次變的是**處理邏輯**。兩者之間沒有連結，所以快取不知道自己該失效。這是「殭屍復活術」（手動改雲端不改部署腳本）的快取版。
**下次**：改任何**解析／轉換／embedding 邏輯**後，動手重跑之前先問「**快取的失效條件包含這個改動嗎**」。不包含就手動清對應段（`zhu-self/.migrate-cache.json`），並且**收案看 embedded 的絕對值**，不看 `fail=0`。
**對應 feedback**：`feedback_ambiguous_signal_not_proof` 第 2 條（完成條件寫成絕對值）當場救了這次。
