# LESSONS 2026-07-15 · 觀察者首晚抓到活血——writeMemory 斷根（ailivex v18.14.1）＋UDN 懶人包視覺總監管線上線（v0.8.0.001）

### L1：backfill 收案前先追寫手
現象：前場補 280 條缺 status 記憶、帳目歸零收案；觀察者首晚報 8 條新缺，當天再長 73 條。
根因：寫入咽喉 writeMemory 從未寫 status 欄——資料手術只動了存量，增量源頭沒關。
下次：任何 backfill/資料清理收案前必答「壞資料誰寫的、還在寫嗎」；修資料和修寫手是兩張工單，只做前者不算解。
對應 feedback：solve_root_not_symptom（資料版）。

### L2：參數要貫穿到所有生產端，不是只給消費端
現象：UDN 懶人包 cardCount 正確存進任務，用戶要 15 張只得 4 張。
根因：參數只有下游 Phase B（拆卡）讀；上游寫文案的聊天角色和 Phase A 完全不知道張數，憑手感寫 4 段——下游再怎麼守約也變不出料。
下次：加參數時列出整條管線的生產端和消費端，每一端都問「它需要知道這個數字嗎」；只接消費端＝參數半吊子。
對應 feedback：backend_client_must_sync 的管線內版。

### L1：顯式覆蓋不隨預設值走（家族雷第二例）
- 現象：ailivex v18 轉正後，Adam 的 tracy/Lilith 仍派工到 v17；v17 降 0 後變死通話
- 根因：canary 釘選是顯式覆蓋，改 DEFAULT 對它無效；轉正流程沒有「清 canary」步驟；v17 留在登錄表（回滾需要）所以解析合法
- 下次：任何「預設值切換」或「服務退役」前，掃所有可能顯式指著它的狀態（access 釘選/流量釘選/min 實例/env 寫死）；更好的是把防禦寫進解析咽喉（standby 旗標模式可複用）
- 對應 feedback：feedback_default_switch_standing_instance（同家族第一例）

### L2：LiveKit agent 平台「能用」與「省錢」的正解是需求喚醒
- 現象：ailive 語音因省錢降 0 直接死；開回常駐又回到 $60/月磚頭費
- 根因：LiveKit agent 出站註冊制，Cloud Run 無法來電喚醒——非 0 即 60 的二選一是假的
- 下次：wake-on-visit（進頁 PATCH min=1）＋idle cron（無活躍房+30 分 PATCH min=0）＋agent 開機蓋章當 ready 信號；全套已在 ailive-platform 可照抄；PATCH 方 SA 記得 artifactregistry.reader
- 對應 feedback：feedback_standing_cost_only_for_instant_readiness（實作範例已補進該 memory）
