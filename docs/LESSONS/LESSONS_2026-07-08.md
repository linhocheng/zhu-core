# LESSONS 2026-07-08 · 第三期遺忘曲線＋平行 session 收尾

## L1：status=empty 是模稜兩可信號——「功能沒開」和「沒有候選」同一張臉
- 現象：gist prod dryRun 回 `status:"empty"`，這在 canary env 沒設、和 env 設了但沒合格候選兩種情況下輸出完全相同。差點拿它當「部署成功」的證據。
- 根因：設計 GistResult 時 disabled 和 empty 共用一個出口；驗證時才發現無法分辨。
- 下次：①驗 env 存在用設定面直接查（`vercel env ls`），不從行為面倒推；②設計 status enum 時「功能關閉」要是獨立值，不跟「開了但沒事做」共用——觀測台（第五期）補。
- 對應 feedback：feedback_ambiguous_signal_not_proof（天條的設計預防版——與其驗證時小心，不如讓信號生來就可分辨）

## L2：平行 session 同日多場，收尾前必 fetch＋讀今天「全部」WORKLOG
- 現象：我收 lastwords 時 ailivex 已被另一場推到 v17.1.0（3.5 期語音道＋連線批次），我的認知還停在自己收的 v16.5.0。若直接覆蓋 ZHU_LAST_WORDS，會把最新戰場（v17 驗收中）洗回舊狀態——快照倒退比沒有快照更毒。
- 根因：lastwords skill 的「先看現場」只看 git log/status，沒明文要求「讀今天所有場次的 WORKLOG 條目再整合」。
- 下次：收尾 STEP 1 前固定跑 `awk '/^## {TODAY}/{f=1} f' WORKLOG.md`，把當天全部場次讀進來，快照寫「全天整合版」不是「本場版」。
- 對應 feedback：feedback_compacted_session_verify_state（同族：續跑前先查現場，別盲信自己的記憶）

## L3（本日另場，出處 WORKLOG 連線批次段）：L10 三犯未遂
- 新公開 route 差點又漏 middleware 白名單，commit 前 staged 清單檢查抓回。「新公開 route 三件套」（route 自帶閘＋白名單＋curl 出處驗證）要成反射。

## L4：跨平台同名生態最容易引用錯例——論證前先問「這個名字住在哪個資料庫」
- 現象：對 Adam 論證 ailiveX canary 必要性時，舉了王彩雲的 118 條記憶當例子——她是 ailive（moumou-os）的角色，不在 ailiveX。被 Adam 當場抓到。
- 根因：兩平台有五個同名角色＋我同一天在兩邊施工，腦裡的例子池混庫了。越順手的例子越可能來自錯的庫。
- 下次：舉任何具體例子（人名/數字/配對）前，內問一句「這是哪個 project 的資料」；同日跨平台施工時尤其要驗。
- 對應 feedback：[[feedback_memory_can_lie]]、L9（舊印象開藥方）的跨平台變體。

## L5：頁面標籤是死的，派工才是真相——UI 版本顯示要吃後端回傳
- 現象：語音視窗左上角「v16」是頁面寫死字串，Adam 被派到 v17 後標籤照樣喊 v16，用戶以為自己在舊版。
- 根因：display 值 hardcode 在頁面，而真相（agentName 派工）在 token route——顯示與決策兩層分裂，assign 制上線那刻標籤就開始說謊。
- 下次：任何「版本/狀態」顯示，一律吃決策端回傳值，不寫死；這也是觀測台的第一原則（畫面顯示的必須是真相＝假中台天條的 UI 面）。
- 對應 feedback：[[sync-truth-principle]]、feedback_ambiguous_signal_not_proof 家族（顯示≠實況）。
