## 施工順序（不可倒的部分已標明）

### 階段 0：清場（順序不可倒）
1. **D2 資料刪除連帶**——案刪→Firestore 子集合＋GCS 資產/成片連帶清
2. **執行全刪**——用剛做好的連帶刪除清掉所有案子（先做 1 才能做 2，否則製造孤兒）

### 階段 1：角色進 DB
3. 資料憲法加 `roles` collection（kind: director/cinematographer、name、persona、prompt、archived）
4. seed 兩個預設角色（導演 v1、攝影師 v1）——prompt 從現有 code 常數搬進去
5. 角色後台（列表/編輯 prompt）＋ CaseDoc 記 directorId/cinematographerId

### 階段 2：兩階段對話主幹
6. 新狀態機（drafting → setup → script → master → upscale → stitch → delivered）
7. `[[ASSET]]` 標記協議＋確定性剝除（UDN `[[DISPATCH]]` 同款）
8. 第一階段對話：導演×客戶 → 設定 → 種資產卡（角色/道具/場景/色調）
9. 攝影師翻譯層：中文意圖 → promptEn（獨立 bridge call，署名落庫）
10. 第二階段對話：導演×客戶 → 劇本 → 種分鏡卡（含秒數/接點）

### 階段 3：三道閘
11. 閘1 母片（沿用 grid job）＋確認才放行
12. 閘2 單圖放大（沿用 keyframes job）＋完成才放行
13. 閘3 縫合前確認＝錢閘（承重牆 #1 搬到這裡）

### 階段 4：收尾
14. CaseRoom UI 重寫（對話為主體）
15. 刪除 V1/V2/V3 相容分支（arting 遺留態、legacy 無母圖分支、舊案 8 秒推導）
16. pinning tests 補齊（新狀態機、標記剝除、三道閘）
17. FOUNDATION.md 重算落檔＋部署＋驗證

## 天條自檢（施工中每步過一遍）

- 算錢/計數/驗證/解析＝程式，不丟 LLM（製片是程式不是角色）
- LLM 輸出一律外層程式 parse/validate，壞了退件不 re-ask 修

- 刪除是不可逆動作——刪之前先確認清單，刪之後驗證桶內狀態
- 承重牆改動要聲明 preserved / moving baseline
