## delta
進場前以為：商業包裝（指數、故事句、情緒燃料）和工程誠實（確定性、零生成）之間要做取捨，包裝＝往「數字可以修飾」滑一步。
現在理解：顧問要的七層皮 100% 用模板句＋程式聚合蓋得出來——指數是透明公式、事實句是規則挑選、作戰計畫是排序輸出。包裝的本質是「資訊架構＋語言翻譯」，不是數字加工；「沒有任何 AI 生成的數字」反而成了商品差異點。移動原因：實際蓋完七層，每一層都找到了確定性實作。
違背了哪條 feedback：無重大違背；「停＝全停」缺口是 Adam 先看見的（增刪改停協議自己定的卻只 enforce 一條管道）——防禦釘收斂點的舊心法，新踩法。

## 教訓
### L1：UI 承諾的狀態語意要在咽喉對全部管道 enforce
- 現象：後台「暫停（排單會被拒）」只對 monitor 為真，intake/audit/content/report 四條照跑，被 Adam 用一單測試月報抓到
- 根因：檢查寫在單一管道的 runner 裡；後來加的管道各自為政，UI 文案變成部分真話
- 下次：任何狀態語意（停/刪/鎖）第一天就釘在分派咽喉（processJob 級），新管道自動繼承；UI 文案寫的是咽喉行為不是單管道行為
- 對應 feedback：feedback_defend_at_convergence_point（新踩法：不是 LLM 輸出防禦，是狀態機語意）

### L2：session 內背景長部署會被清理機制砍
- 現象：./deploy.sh all 放背景跑被 killed，部署中斷在未知步驟
- 根因：本 session 的背景進程清理會砍長時間 Bash 背景任務（昨天砍 watcher/admin server，今天砍部署）
- 下次：部署類長命令前景跑＋timeout 600000；被砍後靠冪等重跑，宣告完成前用雲端狀態驗（scheduler list/service revision），不信 exit code
