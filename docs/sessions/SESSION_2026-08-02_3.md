## 教訓
### L1：build/deploy/雲端 metadata 指令必帶絕對路徑（cwd 漂移昨日 L1 複驗又踩一半）
- 現象：compound command 後 cwd 漂到 repo root 外，`add-metadata --metadata-from-file=startup-script=neko/startup.sh` 讀不到檔（相對路徑）→ 首推失敗，且同批 `instances start` 卻用**舊** startup 把 VM 開起來（走動態 proxy）
- 根因：Bash 工具 cwd 跨呼叫持續但會被前面的 cd 汙染；「在哪跑很重要」的指令沒鎖絕對路徑
- 下次：next/vercel/gcloud metadata/npm 一律 `cd <絕對路徑> &&` 或旗標帶絕對路徑；改 metadata 後記得 VM 要 stop→start 才生效
- 對應：昨天 SESSION_2026-08-02_1 的 L1 同型，這次是複驗——同型二犯的一半（metadata 那次），醒著才沒釀大錯
### L2：「等人操作」的偵測器超時要按人類真實操作時間設，且要能重生
- 現象：capture.cjs 15 分逾時、開機只跑一次，Adam 登入拖過時（卡對話框＋診斷佔用）→ 登入成功但沒人接
- 根因：超時假設「人 15 分內登完」，但真實登入含意外（deep-link 對話框、換登入頁、求助往返）常超；且逾時即死不重生＝單點
- 下次：等人類互動的 async 元件，超時要寬（或持續偵測）＋逾時後可被外部重觸發；D 期開放給同事前必改（同事比 Adam 更慢更容易卡）
- 對應：feedback_async_worker（韌性）＋feedback_mvp_include_input_entry（人怎麼把輸入送進去這一步最容易被低估）
