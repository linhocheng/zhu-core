## 教訓
### L1:跨庫搬運先驗連結活著——re-ingest 過的主檔指著死鏈
- 現象:兩件產品的 knowledgeIds 全 MISSING(源庫後來重新入庫,舊段落被刪,主檔沒更新指標)
- 根因:聚合 doc 的外鍵陣列不隨被指對象的生滅維護——讀側看起來完整,解引用才知道死
- 下次:跨庫搬運三層 fallback 順序:①解引用驗活(exists+content>20)②標題前綴撈活段落(複合索引沒有就全量本地濾)③退回主檔欄位+確定性清洗(圖說垃圾切尾)
- 對應 feedback:memory_can_lie(資料庫版——指標也會說謊)

### L2:量測探針自己要先被驗證——「等文字」不等於「等資料」
- 現象:煙測等到「件商品」字樣就開始等圖,但字樣在 0 件時就 render 了;探針量的是 hydration 中間態,25s PENDING 差點誤診 App 斷圖(圖檔 curl 200+PIL 可解)
- 根因:React 頁的「出現某字」和「資料到位」是兩個時刻;把中間態當終態量,量出來的是幻覺
- 下次:動態頁探針兩段式——先等元素數量到位(document.images.length≥N),再等狀態到位(every complete&&naturalWidth>0);誤診方向要雙查:標的真壞 vs 探針量錯
- 對應 feedback:ambiguous_signal_not_proof(量測工具版)

### L3:改名不是改一筆,是掃引用——正名的「兩份即是零份」
- 現象:慕絲花本體正名後,雪玉如初的使用流程段落還引用舊名,驗收抓到殘留
- 根因:名字散在引用處;改本體不掃引用=庫內兩個名字並存,檢索兩頭都命中一半
- 下次:任何正名操作,收案信號=corpus 全域 grep 舊名為零;修法=受影響 doc 整份確定性替換+刪除重入(embedding 跟著新文本重算)
- 對應 feedback:defend_at_convergence_point+破索式(兩份即是零份)
