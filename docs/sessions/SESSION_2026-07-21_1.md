## delta

進場前以為：三站 CSP nonce 化是「同一份模板複製三遍」的機械活——寫一次 middleware、貼三站、收工。
現在理解：**同模板複製到多站，真功夫在「每站用什麼方式破」，而破法只有逐站真瀏覽器測才抓得到**。同一份 nonce 模板：geo 一次過、UDN 撞 Next 16 靜態頁死白頁（curl 0/15 nonce，差一步部署就是全站登入死頁）、ailiveX 撞外部 Google Fonts 被擋。三站三種不同的破法，沒有一個是讀模板能預見的。
移動原因：模板消滅的是共通結構，但每站的 Next 版本／字型載法／靜態頁分布／既有 middleware 各不同，這些「模板沒覆蓋的差異」正是會咬人的地方。curl 只證「script 帶了 nonce」，證不了「瀏覽器真的執行、頁面還活」——所以我全程用 playwright headless 真瀏覽器＋軟導航當 hydration 鑑別信號。
違背了哪條 feedback：無違背。反而 [[feedback_flagged_risk_must_be_verified]]（標了不等於驗了）＋[[feedback_ambiguous_signal_not_proof]]（鑑別信號）＋[[feedback_ui_conform_no_patch]]（動 UDN 前讀 AGENTS.md 官方 doc 才動）全正向實踐。

## 心法狀態

- 「鑑別信號」全程主角：每站都定義「修對會看到 script 全帶 nonce＋軟導航 window 未重載」才算活；UDN `0/15 nonce` 若沒真測、直接部署＝全站登入死白頁；部署後再用同信號打 production（新 CSP header＋兩請求 nonce 不同＋流量 revision 無分裂）
- 「動手前讀官方 doc」：UDN 撞 proxy.ts 改名時，照 AGENTS.md 明令先讀 `node_modules/next/dist/docs/` 才動，doc 直接給了「靜態頁 nonce 對不上→force-dynamic」的正解
- 「防禦釘在收斂點」：force-dynamic 釘 root layout 一處，保證全站每頁＋未來新頁都不會靜默破 CSP，不逐頁補
- 「發現真 finding 不假設」：ailiveX 字型被擋是真 violation，沒揮手帶過而是 grep 出 @import 來源、加放行、重測 0 violation

## 教訓

### L1：同模板複製到多站，每站都要逐站真瀏覽器測——模板過一站不等於全過
現象：同一份 CSP nonce 模板，geo 一次過、UDN 撞 Next 16 靜態頁死白頁（0/15 nonce）、ailiveX 撞外部 Google Fonts 被 style-src 擋。三站三種不同破法。
根因：模板消滅共通結構，但每站的框架版本／字型載法／靜態頁分布／既有 middleware 各不同——這些差異正是模板沒覆蓋、會咬人的地方。
下次：複製前端加固模板到多站，逐站跑真瀏覽器測（playwright headless），收三信號：script nonce 覆蓋 N/N、0 CSP violation、client 軟導航（window 未重載＝真 hydrate，比 __next_f 可靠）。心裡冒出「一樣的改法應該都會過」就是要逐站真測的訊號。
對應 feedback：[[feedback_flagged_risk_must_be_verified]]＋[[skill_csp_nonce_per_site_headless_verify]]。

### L2：Next 16 三個破壞性雷（升級/加固 Next 平台前必知）
現象：middleware.ts 在 16.2 改名 proxy.ts（16.1 仍認 middleware.ts）；靜態頁 nonce 對不上→strict-dynamic 全擋死白頁；`window.__next_f.length` hydrate 後被清空、不是有效探針。
根因：Next 16 一系列 breaking changes（AGENTS.md 開頭就警告「This is NOT the Next.js you know」）。
下次：動 Next 16 前先核版本＋讀 `node_modules/next/dist/docs/`；nonce 必配 root layout force-dynamic；hydration 驗證用軟導航不用 __next_f。
對應 feedback：[[reference_nextjs16_csp_nonce]]（完整技術細節）。
