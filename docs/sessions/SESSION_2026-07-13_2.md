## 教訓

### L1：要編輯的檔案，第一次接觸就用 Read 工具開，不用 Bash cat/sed 代替
現象：三次 Edit 被「File has not been read yet」擋——每次都是先用 Bash sed/cat 看過內容，自以為「讀過了」。
根因：harness 的 Edit 前置條件認的是 Read 工具呼叫，不是「內容有沒有進 context」；用 Bash 看檔在機械層等於沒讀。三犯同型＝context 退化的行為信號（每次都「知道規則」但手滑）。
下次：探勘用 Bash grep/sed 沒問題，但**確定要改的檔，動手前補一次 Read 工具**（讀目標區段即可）；被擋第一次就該切換習慣，而不是第三次。
