## delta
進場前以為：M3/M4 是「code 完成待現場驗」，驗一驗就好。
現在理解：**真實機驗證會逼出設計看不到的坑，而且好幾個是產品級的**——neko maxTouch→Meta 送 App 頁（不驗永遠不知道客戶登不進來）、capture 漏 clientId 欄位（合成測試過但直捕路徑漏）、WIF 接 Firestore 踩四坑（讀 code 全看不出）。「沙推/合成測試通」和「真帳號端到端通」之間隔著四個真 bug。
移動原因：合成 session capture 顯示 health=connected 密文418B「看起來全通」，但真帳號一跑，maxTouch/clientId/index/留言 四個坑接連冒出來——每個都是真信號逼出來的，沒有一個是我事先想到的。
違背了哪條 feedback：無（本場是正循環，而且是「能本機重現就不等遠端」「標了風險要驗」的正面兌現——我沒宣告「應該通」就收，一路驗到真爆文落 Firestore）。

## 教訓
### L1：真實機端到端會逼出設計/合成測試看不到的產品級坑
- 現象：合成 session capture「看起來全通」（health=connected），真帳號一跑接連冒 4 個坑：neko maxTouch=10→Meta 送 App QR 頁、capture 漏 clientId 欄位、複合索引缺、留言 selector 漂移
- 根因：合成測試驗的是「我想像中的資料流」，真帳號驗的是「真實系統的每一層契約」——尤其外部系統（Meta 的裝置判定、Firestore 索引）的行為讀 code 看不出
- 下次：對外產品「能不能做」的收案標準是真帳號端到端，不是合成 200；碰外部系統（登入/反爬/第三方 API）尤其要真帳號跑一遍
- 對應 feedback：local_replay_over_remote_wait + flagged_risk_must_be_verified + 新 glue_layer_errors_lie
### L2：neko/雲端瀏覽器的裝置指紋會被反爬判定（產品級）
- 現象：neko maxTouchPoints=10（觸控），Meta/IG/Threads 判行動裝置→送「下載 App」QR 頁而非 web 登入表單，客戶根本登不進來
- 根因：neko 為 WebRTC 互動預設開觸控，但這讓瀏覽器指紋像平板
- 下次：自建雲端瀏覽器接會反爬的站，先驗「目標站對這個瀏覽器送什麼頁」——UA/maxTouchPoints/viewport 都是指紋；--touch-events=disabled 是這次的解
- 對應 feedback：新 glue_layer_errors_lie（膠水層/邊界層行為要真信號驗）
