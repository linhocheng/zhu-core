## 教訓
### L1:收權桶之前,「誰在匿名讀」要查到功能層——公開可能是設計不是漏洞
- 現象:早上報告把 documents/ 公開當風險;查引用發現 doc-worker 回傳公開 URL 給瀏覽器直開,「知道連結能看」是文件檢視器的功能語意
- 根因:把「公開=危險」當直覺,沒先問「這個公開在服務誰」
- 下次:收權三步=①每個前綴誰匿名讀(功能層)②真洞常在權限的「附帶能力」(objectViewer 附帶 list=可列舉,連結隱私瞬間裸奔)③修法選「保留 get 殺 list」這種最小刀(legacyObjectReader)
- 對應 feedback:verify_references_before_retiring(公開資源版)

### L2:LLM 會把單位讀成語意——「3.1 分」的評分幽靈
- 現象:報告歸納段把「平均 3.1 分(鐘)」寫成「平均分落在 3.1 分,屬中段偏低」——整段品質判斷建立在不存在的評分制上
- 根因:facts 字串的「分」有歧義,模型撿了機率高的解讀(保養品+分數=評分)
- 下次:餵 LLM 的事實字串,單位寫全稱(分鐘/新台幣/場)+system 排除不存在的制度(「本活動無評分制」);歧義字面=餵料層的確定性責任,不是模型的錯
- 對應 feedback:deterministic_work_belongs_in_code(餵料措辭版)

### L3:訓練沉澱會重複入庫——共創管線缺冪等
- 現象:Kane 23 份知識 7 份是同標題重複(最多同課×3)——Peggy 每教一次、審核轉正一次,就多一份
- 根因:knowledge-proposals 轉正走 ingestKnowledgeDoc 無同名檢查
- 下次:任何「人工反覆觸發的入庫管線」第一天就要冪等(同 characterId+title 跳過或警示);去重法=同標題留內容最長,deleteKnowledgeDoc 連塊清
