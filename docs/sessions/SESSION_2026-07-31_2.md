## 教訓
### L1:LLM 工具呼叫是機率輸出——嘴巴說「記錄好了」不等於工具開了火
- 現象:v21 角色口頭確認「舒缓面膜三入,选定了!」,但 record_choice 沒 call,data channel 無事件,/api/gift 無請求;同一 prompt 前一場有 call(2 場 1 中)
- 根因:工具呼叫由 LLM 決定=機率;prompt 加壓只抬機率不保證
- 下次:凡 LLM 側動作 gate 業務結果(落庫/寄送/計費),結果落地點必放確定性兜底;本案真相源=受訪者親口「N號」在逐字稿裡,regex 可靠抽回
- 對應 feedback:deterministic_work_belongs_in_code、ambiguous_signal_not_proof(工具呼叫版)

### L2:Firestore 不收 undefined——清洗函數「空值不放 key」而不是「放 undefined」
- 現象:campaign 建立 500,`Cannot use "undefined" as a Firestore value (found in field "script.productNotes")`
- 下次:寫 Firestore 的清洗層,選填欄位一律條件式加 key;或全庫開 ignoreUndefinedProperties(沒開就別依賴)

### L3:Vercel deploy exit 0 ≠ 下一發請求打到新代碼
- 現象:部署後立打 admin list,回的是舊行為(無兜底);8 秒後重打=新行為全對,差點誤判「兜底沒生效」
- 下次:deploy 後驗證要嘛等傳播(數秒),要嘛打帶新鑑別信號的端點確認版本,不拿第一發當判決
