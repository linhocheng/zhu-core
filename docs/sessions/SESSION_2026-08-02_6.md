## 教訓

### L1：背景任務的完成通知不等於成功
現象：Cloud SQL create 丟背景（`| tail -2`），任務完成通知 exit 0，我宣告「建好了」；實際 gcloud 印了 400 錯誤（PG17 預設 ENTERPRISE_PLUS 不吃 db-f1-micro）。
根因：管子吃掉 exit code＋背景通知只看殼的退出碼；「completed」≠「succeeded」。
下次：背景 gcloud 類指令結尾必帶 `; echo EXIT=$?` 且不接管子；收到完成通知先 Read output 檔找成功的鑑別信號（RUNNABLE、Created），才准宣告。
對應 feedback：feedback_pipe_eats_exit_code（驗證+1）＋ feedback_ambiguous_signal_not_proof。

### L2：多後端共用一個 base URL env 是路由地雷
現象：附件強制直連 API，卻沿用指向 bridge 的 llmBaseUrl → x-api-key 敲 bridge 門 → 401，log 還寫「Anthropic API 401」誤導。
根因：一個 env 變數承載兩種後端的位址；「強制切後端」的分支只切了 header 沒切 URL。
下次：多後端並存時，每個後端的 base URL 各自鎖死（bridge 用 env、官方 API 用常數），切換點一次切整組（URL＋auth＋body 格式），不留半切狀態。
對應 feedback：feedback_glue_layer_errors_lie（驗證+1）。
