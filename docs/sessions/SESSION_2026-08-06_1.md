## delta
- 進場前以為：「90% 重做」意味著要開新 repo，或至少要留一層相容
- 現在理解：**「案子全刪」這個授權，把重寫的成本結構整個換掉了**。沒有舊資料就不需要相容層，於是可以在同一個 repo 裡真正重寫幕次流程，同時保住引擎層與地基。判斷重寫要不要開新家，關鍵不是「改多少」，而是「有沒有舊資料要伺候」

## 教訓

### L1：shared 層不准 import lib 層——worker 那邊沒有 lib
- 現象：把「導演談定的鏡頭→分鏡表」寫進 `shared/db.ts`，裡面 `await import('../lib/chat-run')`
- 根因：shared 是 web 與 worker 共用的，worker 編譯進 Cloud Run Job 時沒有 `lib/`——本機 build 會過，雲端 job 起來才炸
- 下次：往 shared 加東西前先問「worker 那邊有這個依賴嗎」；跨層依賴一律往上搬（lib 可以用 shared，反過來不行）
- 對應 feedback：feedback_glue_layer_errors_lie 的預防版——這種錯會在最遠的地方以最無關的樣子爆出來

### L2：型別系統是重構的探照燈，不是路障
- 現象：改 `CaseStatus` enum 後 `tsc` 一次吐出 9 個錯，散在 db/guards/6 個 route
- 根因（好的那種）：資料憲法是唯一真相源，改它就會照亮所有讀寫端
- 下次：大重構先改型別再改實作——讓編譯器列清單，比自己 grep 可靠
