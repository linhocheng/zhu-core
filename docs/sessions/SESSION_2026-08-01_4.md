## delta
進場前以為：「意圖偵測」是個要另起爐灶的分析系統（切角分析情報站的大工程的一部分）。
現在理解：**意圖層是掃描管線的一個薄層**——關鍵字管召回（確定性）、意圖管理解（LLM 判斷），中間用「證據原句鐵律」焊住不讓 LLM 漂。一吋蛋糕人肉先跑讓 schema 從資料長出來（光譜 enum 不是憑空設計的），機器版對人肉版 ground truth 一字不差＝管線可信。移動原因：Adam 用一個具體問題（「卸妝粉刺裡哪個在問產品好不好用」）逼出了原型，原型逼出了 schema——需求→樣本→結構，不是結構→需求。

## 教訓
### L1：Edit 前用 Read 工具讀檔，Bash cat 不算數——同型滑倒 7 次
- 現象：整場 Edit-before-Read 被 guard 擋 7 次（globals.css/collections/auth/routes/setup-iam…），每次都是先用 Bash cat/grep 看過檔案就以為可以 Edit
- 根因：工作記憶把「看過內容」和「工具鏈認可的已讀」混為一談；Bash 讀的不進 Edit 的前置檢查
- 下次：要改的檔案一律先 Read 工具（哪怕只 Read 目標行段）；Bash grep 只用來「找位置」不用來「取代讀」
- 對應 feedback：醉酒指數的工具滑倒信號——這場就是靠它累到 8 分
### L2：接外部服務前先做「分裂判決」設計——多源交叉驗，裁判給行為不給標籤
- 現象：靜態 IP 的 ASN 一家說 hosting 一家說不是（2:1）
- 根因：IP 信譽資料庫各家分類法不同，單源是雜訊；真正的裁判是目標平台的行為（Threads 放不放行）
- 下次：買 IP/proxy 類資源驗收＝多源 flag 交叉＋真實負載實測雙軌，標籤打架時以行為為準、標籤記為觀察項
- 對應 feedback：ambiguous_signal_not_proof＋glue_layer_errors_lie
