## 教訓
### L1：跨字系的文本比對，歸一字系是前置條件不是優化
- 現象：分聲比對 AI 0 句命中——對話 doc 存簡體（Soniox/TTS 管線）、Apple STT 出繁體；更陰的是簡繁共用字讓短句撞出 0.35+ 假分數，錯標「人類」
- 根因：bigram/cosine 這類表面相似度在字系不同時全滅，但不會報錯，只會靜默給出低分＋噪音分——比「完全失敗」更難察覺
- 下次：任何中文文本比對（檢索/去重/對賬）先問兩邊字系；不確定就兩邊都過 opencc 再比。跟 cross_register_retrieval（語域）同構：**表面相似度的前提是同一表面**
- 對應 feedback：reference_opencc_s2t_pitfalls 新增面向

### L2：Explorer 勘查報告的資料流結論要抽一條驗現場
- 現象：勘查兵報「語音逐字稿存 conversations/{userId}_{characterId}」，實際存 `ailivex-voice-...` 獨立 doc——分聲整條參照線建在錯的 doc 上，跑通了才發現全錯
- 根因：勘查兵讀 save_conversation 簽名（conv_id 參數）沒追 conv_id 的實值來源（token route 的字串模板）；我直接採信，沒抽驗
- 下次：子代理的「資料寫到哪」結論，動工前抽一筆真資料驗（一條 query 的事）；跟 raw_query_not_ui_truth 同族——**別人的報告也是記憶，會說謊**
- 對應 feedback：diagnosis_verify_before_write／memory_can_lie 家族
