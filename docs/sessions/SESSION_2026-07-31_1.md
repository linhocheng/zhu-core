## 教訓
### L1:記憶擋不住手癖——pipe 吃 exit code 二犯,防禦改釘指令模板
- 現象:`npm run build 2>&1 | grep ✓ && git commit && push`,build 其實 Type error,grep 命中「✓ Compiled」exit 0,壞代碼推上 git(Vercel 端 build 擋下,線上無傷)
- 根因:上月已刻 feedback_pipe_eats_exit_code,但「想修剪輸出」的手癖頻率遠高於記憶被喚起的頻率
- 下次:退出碼要 gate 下游的指令,唯一合法形狀=`cmd > /tmp/x.log 2>&1; EXIT=$?; grep 摘要 /tmp/x.log; [ $EXIT -eq 0 ] && 下游`;手要打 `| grep` 前先問「這條的退出碼有沒有人在聽」
- 對應 feedback:feedback_pipe_eats_exit_code(已升級為禁令模板版)

### L2:Chrome 假音檔旗標是死路,語音自動測試正解=WebAudio 注入
- 現象:`--use-file-for-fake-audio-capture` 餵任何格式 WAV(48k/16k/canonical 標頭)全是靜音(peak 0.000);純音生成器有訊號——檔案路徑在新舊 headless 都不工作
- 正解:頁面留 `window.__room` debug 掛鉤 → puppeteer evaluate 內 fetch WAV→AudioContext.decodeAudioData→MediaStreamDestination→`publishTrack(track,{source:'microphone'})`——確定性注入,合成語音(`say -v Meijia`)當假訪客,全自動驗完整語音對話環
- 下次:所有語音功能的 e2e 都可用這套;假訪客音檔別墊長靜音(量測窗口會全落在靜音段誤判)

### L3:LLM 轉手的選項標籤會漂移——正典律
- 現象:訪綱給繁體禮物清單,agent 的 show_options 把標籤重打成簡體「1号」;前端等「1號」偵測失敗,字串比對驗證也會炸
- 根因:標籤經 LLM 轉手=經過機率引擎,簡繁/改寫/增減字無保證
- 下次:畫面渲染一律用己方正典清單(LLM 事件只當觸發器);語音選擇用編號 regex 確定性對映回正典;永不比對 LLM 產的字串
- 對應 feedback:deterministic_work_belongs_in_code、defend_at_convergence_point

### L4:port 殭屍讓新磁碟配舊記憶——真相分裂的 dev server 版
- 現象:pkill -f 'next start' 沒殺乾淨,舊 server 霸 :3000 用記憶體舊 manifest 服務新 .next 磁碟 → ChunkLoadError 連環,rm -rf .next 重建也「無效」(因為根本不是磁碟問題)
- 下次:換 build 重啟一律 `lsof -ti :PORT | xargs kill -9`,再驗「served HTML 引用的 chunk 檔名=磁碟檔名」才算重啟完成
- 對應 feedback:killall_vs_pkill(同族——殺進程要用抓得到的把手)
