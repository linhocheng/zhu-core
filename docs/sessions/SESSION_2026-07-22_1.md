## delta
進場前以為：用哪個 API 憑證是實作細節——key 在手、驗過有效，就沿著用。
現在理解：**憑證選擇是帳本歸屬決策，不是認證方式選擇**。Gemini API key 的成本進 key 持有者的帳，Vertex ADC 的成本進 GCP 專案的帳——客戶平台的生成費用記到別人的 key 上＝帳本分裂，而且這決策做下去之後所有 cost 監控、預算閘、稽核都建立在錯的地基上。
移動原因：Adam 中途一句「等 為何不用gcp」。我當時正沿著「他問 Gemini key 可以怎麼做」的探索慣性把測試線直接鋪成施工線——被點醒後真算一次，Vertex 淨賺三個結構優勢（零密鑰/帳單歸戶/GCS 直寫），換線成本半小時。
違背了哪條 feedback：feedback-bridge-first 的家族擴張——「能走哪條線」的第一問是成本歸屬和結構，不是手上有什麼能用。

## 心法狀態
- 「沙推不是驗證」正面實戰：worker 動筆前每個 API 假設都先 probe（首尾幀形狀/Vertex 模型名/輪詢方式），三發 probe 抓出三個文件錯誤，worker 一次寫對零返工
- 「心跳帶帳」從 geo 學費直接搬進新管線第一版（不是之後補）——RAI 失敗那輪 cost=$0.8 留帳、續跑不重複累計，設計即驗證
- 「確定性工作用程式」：拼接 ffmpeg、裁切 ffmpeg、成本計算純函數，全程零 LLM

## 教訓
### L1：API 文件的範例形狀會騙人——動筆前每個假設真打一發 probe
- 現象：官方文件說 image 用 inlineData（實測 400）；Gemini API 模型名 -preview 在 Vertex 404（GA 是 -001）；Vertex 輪詢不是 GET operation 是 POST fetchPredictOperation。三個假設全靠 $0.8 的 probe 抓出，worker 一次寫對
- 根因：文件由小模型摘要＋多產品線（Gemini API/Vertex）形狀不同步；訓練資料裡的舊 SDK 記憶更不可信
- 下次：接新 API 的 SOP＝最小 probe 先行（一發真請求驗形狀）→ 才寫生產代碼；probe 成本遠低於部署後在 job log 裡除錯
- 對應 feedback：[[feedback_sandtable_not_validation]]（正面案例）

### L2：憑證選擇是帳本歸屬決策——「能用」不等於「該用」
- 現象：沿著「Gemini key 可以怎麼做」的探索慣性，差點把個人 key 鋪成客戶平台的生產線；Adam 一句「為何不用gcp」點醒
- 根因：探索階段的工具（手邊的 key）無縫滑進施工階段沒有重新決策；「驗過有效」給了虛假的正當性
- 下次：探索轉施工的關卡加一問——這條線的錢進誰的帳？密鑰誰管？跟平台既有結構（ADC/同專案）一致嗎？
- 對應 feedback：[[feedback_bridge_first]] 家族

### L3：內容安全過濾是新聞平台的物理環境，失敗路徑要當一級公民設計
- 現象：校園毒品議題圖第 2 段被 Vertex RAI 擋，同圖同判定穩定重現；被擋不收費
- 根因：新聞素材天然含敏感題材，RAI 過濾不是異常是常態環境
- 下次：接生成式 API 的平台，RAI/內容政策失敗路徑第一天就設計（reason 白話寫回＋已燒成本保留＋斷點續跑）；UX 引導語（換圖/改描述）記帳本待灌
- 對應 feedback：[[skill_cost_on_heartbeat_failure_accounting]]（失敗路徑一級公民的內容政策版）
