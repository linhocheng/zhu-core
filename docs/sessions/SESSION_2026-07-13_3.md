## 教訓

### L1：驗證指令本身也是洩密面
現象：驗 SA key JSON 格式時 `node -e require()` 吃到非 .json 副檔名 → 當 JS 解析 → SyntaxError 把整把 private key 印進 session。
根因：對含密檔案跑任何會「引用檔案內容報錯」的指令（require/import/syntax check），錯誤訊息就是內容洩漏通道。
下次：讀含密檔一律 `fs.readFileSync + JSON.parse`（錯誤只報位置不吐全文）；驗證含密檔的指令先想「這指令失敗時會印什麼」。洩了就當場撤銷重發，不心存僥倖。
對應 feedback：不暴露密鑰紅線；feedback_validate_secrets_before_inject。

### L2：Edit-before-Read 同型雷跨場二犯
現象：next.config.ts 又被「File has not been read yet」擋（上場三犯、本場一犯）。
根因：Bash cat 看過內容給了「讀過了」的假記憶；跨 session 習慣未固化。
下次：規則升級成「要編輯的檔，本 session 內沒 Read 過就先 Read」，不管多有把握、不管 cat 過幾次。
對應 feedback：skill_drunk_check_protocol（工具滑倒計分項）。
