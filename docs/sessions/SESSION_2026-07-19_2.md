## delta

進場前以為：天條是「規範」——把踩過的雷寫下來，讓未來的我遵守。地基藍圖也是這個性質，一份寫給未來的清單。
現在理解：好的天條不是規範，是**機制**——帳本＋儀式＋鑑別信號三層互鎖，當天就能咬人、驗證自己。今天立的地基天條當天就實戰三次，三次都靠「鑑別信號」抓到我自己的漏：①ZAP 重掃打臉我「消掉 Medium」的初報（保守 CSP 擋不住 XSS）②Semgrep 上線第一秒抓到我推的 workflow 自己用 unpinned action（供應鏈規則）③本機 semgrep 通但 CI 紅（我先掃後寫 workflow，本地漏掉 workflow 檔自己）。規範是死的、要靠自律讀；機制是活的、會主動咬。這正是「確定性工作用程式」的上位版——連「守紀律」這件事本身都不該靠自律，要靠機器天天掃。
移動原因：一天內親眼看天條咬我三次，且三次都是機器抓的、不是我自省抓的。
違背了哪條 feedback：無違背，反而是被救。BUILDING_PROTOCOL 早記的「本機通≠CI通」雷這次以新形態出現（先掃後寫→檔案集不一致），但因為堅持「宣告修好前看鑑別信號」（等 CI 真綠、重掃、手動觸發 DAST）全被接住。

## 心法狀態

- 「確定性工作用程式」升級到治理層：機器把關不靠自律（資安 CI＝記憶觀察者的資安版）；連「遵守天條」都機制化
- 「宣告修好前先指鑑別信號」全場主角：ZAP 重掃、CI 真跑、DAST 手動觸發——每一步都拒絕「我寫了就算」，要「機器驗了才算」。若只 curl 看 header 在不在就會對 Adam 說謊
- 「pinning test 變紅＝系統正常運作」首次落地：Semgrep 抓自己 unpinned action，我沒關規則（剪警報線）而是 pin SHA（真加固）
- 「防禦釘在收斂點」＝地基帳本：三張表（地基/技術債/承重牆）把散落決策釘進 repo
- 平行施工規約：四 repo 施工，commit 只 add 自己的；audit 確認別場髒樹不是我的

## 教訓

### L1：接 CI 的 workflow 檔會被自己的 SAST 掃到——先掃後寫等於漏掉自己
現象：本地 semgrep 預跑 75 檔 0 findings，push 後 CI 76 檔抓到 5 findings，全指向剛推的 workflow 檔自己（unpinned action）。
根因：我「先本地預跑掃描、後寫 workflow」，本地掃的時候 workflow 還不存在——本地檔案集少一個。CI clean checkout 掃到 workflow 自己。
下次：寫完 workflow 後，本地要在「workflow 檔已存在」的狀態重跑一次 SAST（跟 CI 同檔案集）再 push；接 CI 時假設「掃描器會掃到自己」，workflow 的 actions 直接 pin SHA。
對應 feedback：本機通≠CI通（BUILDING_PROTOCOL）的檔案集變體。

### L2：新 SAST 上線第一秒抓到的問題可能在它自己身上——那是正常運作不是誤報
現象：Semgrep 首跑就紅，findings 全在 CI workflow 檔（供應鏈規則：action 該 pin SHA 不用可變 tag）。
根因：unpinned action（@v4 tag 可被重指向惡意 commit）是真供應鏈風險，Semgrep 判對了。
下次：新警報線抓到自己時，先問「它說得對嗎」而非「怎麼讓它閉嘴」；對的就修（pin SHA），不對才 ignore。關規則＝剪警報線。
對應 feedback：pinning test 變紅＝系統正常運作（holygrail2 收編當天實踐）。
