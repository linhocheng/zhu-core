## delta
進場前以為：HTTPS 是安全工程（防外洩）。
現在理解：**這一刀同時是可用性工程**——8080 永遠鎖 127 之後，連接儀式的「每次開防火牆給同事浮動 IP」整組蒸發，而那正是同事連不上的頭號主因。安全做對的時候不是加摩擦，是減摩擦；「多一層會壞的元件」的反面是「一層把兩個問題都收掉的元件」。移動原因：改 route 時發現 firewallAllow 的唯一存在理由（8080 要對外開洞）被 tunnel 拔掉了。

## 心法狀態
- **鑑別信號先寫**：全程五段驗證（tunnel/status route/metadata/handle/掃描）每段先寫 X/Y 再看。
- **誠實收案**：handle cookie 路死巷，log 白紙黑字「抓不到」，不硬凹「管線建好就算完成」——管線是真的、資料不在也是真的，兩句都說。
- **成本模型蓋在真數據上**：先撈 Firestore/executions 才寫表，順帶抓到 timeout 雷——重算的價值一半在數字一半在盤出地雷。

## 教訓
### L1：cwd 漂移三犯（next build→gcloud metadata→vercel deploy），該上結構性處方了
- 現象：`npx vercel --prod` 在 repo root 跑→「No Next.js version detected」（root 也有 .vercel link 加重誤導）；同型已三犯（8/2_1 next build、8/2_3 gcloud metadata、本場 vercel）
- 根因：Bash cwd 跨呼叫持續且被前面 cd 汙染；「在哪跑」敏感的指令（build/deploy/metadata）沒有一律鎖絕對路徑的肌肉
- 下次：**deploy/build/metadata 類指令一律 `cd <絕對路徑> && ` 開頭**，不例外；本場後半已照做（vercel 二推、fanout 均帶絕對 cd）
- 對應：SESSION_2026-08-02_1 L1、_3 L1 同型；三犯=高利貸，處方從「記得」升級為「格式」：往後這類指令寫進 session 檔接棒段時直接附完整絕對路徑指令（本檔接棒段已照辦）
