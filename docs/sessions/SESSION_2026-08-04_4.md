## delta
- 進場前以為：交付的邊界是「API 回 200＋資料落庫」。
- 現在理解：**交付的邊界是使用者的眼睛**——中間隔著瀏覽器快取、CDN、UI 渲染，每一層都能讓「成功」變成「看起來沒發生」。今天這隻 bug 全程沒有一行錯誤 log。
- 移動原因：Adam 說「我感覺好像不行」而所有伺服器端信號都說「行」——兩邊都對，中間那層才是現場。
- 同型上一次：feedback_raw_query_not_ui_truth（直撈 DB 不能當 UI 行為回報）——今天是它的鏡像：後端成功也不能當使用者看到。

## 心法狀態
- 「鑑別信號」再進化：使用者說「感覺不對」時，鑑別信號要設在**他那一端**（標頭/md5/畫面），不是我這端的 API 回應
- 引擎政策的失敗形狀不只有「拒絕」，還有「悄悄給你一個閹割版」——log 全綠、圖有生成、內容被抹。要用眼睛驗收不能只看狀態碼
- 醉酒指數 6（同日長 session：壓縮接手 +3、工具滑倒 +2、gcloud token 二度死 anchor 抖動 +1）——已到報數線，主動報過，全程只做可逆操作

## 教訓
### L1：不可變資源才配長快取——會被覆寫的路徑要嘛短快取要嘛版本化，兩者擇一必須顯式選
- 現象：資產「這張重生」成功但客戶永遠看到舊圖，零錯誤 log，一年內不會自癒
- 根因：`uploadBuffer` 對所有路徑一律掛 `max-age=31536000`——那是為「幀圖生成一次就不動」設計的常數；V2 加了重生功能後同一路徑變成可變資源，常數沒跟著改
- 下次：任何 `uploadBuffer`/CDN 寫入點，先問「這路徑會不會被同名覆寫」；會＝must-revalidate 或版本化。已上傳的舊物件別忘 `gsutil setmeta`（新策略不追溯）
- 對應 feedback：feedback_capacity_constants_expire ＋ feedback_defend_at_convergence_point
