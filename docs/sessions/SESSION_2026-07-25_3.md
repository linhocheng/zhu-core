## 教訓
### L1：未用依賴帶傳遞漏洞——動 audit 前先查 import，移除未用比 audit fix --force 安全
- 現象：web npm audit 16 高危，多數是 firebase-admin 拖的 google-cloud 傳遞鏈（google-gax/gcp-metadata/gaxios）
- 根因：firebase-admin 是 pitfall #4 嘗試留下的未用依賴（db.ts 只在註解提及、零 import），卻整串依賴進 lockfile
- 下次：npm audit 一堆傳遞漏洞時，先查「這個直接依賴真的被 import 嗎」——未用的移除（16→11、還瘦 bundle），比 `audit fix --force`（升大版本破壞性）安全對症
- 對應 feedback：genericize_to_leaf_nodes 的近親（耦合殘留在沒人用的地方）
### L2：CI/掃描器首跑必抓 findings——逐條分真偽，不一律關也不一律修
- 現象：Semgrep 首跑 12 blocking findings
- 根因：好的 SAST 一定會抓到「真問題＋誤報」混雜；一律關規則=閹掉 CI，一律照修=被誤報綁架
- 下次：逐條分三類——真修（GCM authTagLength/Dockerfile 非 root/Actions 釘 SHA，真驗）、標註誤報帶理由（metadata http/curl|bash 自有 VM，**nosemgrep 須與命中同行才生效**）、已評估風險（Next.js 傳遞 high 記 D13）
- 對應 feedback：deterministic_work_belongs_in_code（掃描是機制）＋ flagged_risk_must_be_verified（非 root 改動真掃驗）
### L3：GCP 帶 override 執行 Cloud Run Job 需 run.jobs.runWithOverrides（run.invoker 不夠）
- 現象：runScanJob 帶 CLIENT_ID env override 打 jobs:run→403，radar-web 有 run.invoker（含 run.jobs.run）卻仍擋
- 根因：帶 containerOverrides 執行需獨立權限 `run.jobs.runWithOverrides`，run.invoker 只含無 override 版的 run.jobs.run
- 下次：cron/後端觸發 Cloud Run Job 且帶 env override→SA 要 run.jobs.runWithOverrides；補自訂角色不用整包 run.developer
- 對應 feedback：gcp_new_project_iam 家族（IAM 權限名的隱蔽差異）
