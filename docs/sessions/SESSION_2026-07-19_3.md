進場前以為：審協作者的請求＝審他要什麼、成本多少（A1「請補 openai/perplexity key」看起來就是個開關任務）。
現在理解：**協作者的情報也是一種「記憶」，同樣會說謊**——A1 三面驗（開關/key/計費）發現四引擎早已名副其實，請求基於過時認知；照單全收就會「執行」一個不存在的任務還回報「開好了」。對協作者的請求先驗前提再動手，跟對自己的記憶先看現場是同一條紀律的外延。

違背了哪條 feedback：無；是 feedback_memory_can_lie 的新臉（別人的記憶）。

## 教訓
### L1：協作者的請求先驗前提，再動手
- 現象：WAITIN 請求「A1 補 openai/perplexity key」附成本試算；三面驗證發現四引擎開關全開、key 全有效、真實 runs 四引擎各 60+ 筆 ok——任務不存在
- 根因：把協作者的現況描述當事實輸入；他的認知停在舊版預設（雙引擎），沒人驗
- 下次：任何「幫我開/修/補 X」先驗 X 的現況（設定面+憑證面+計費面），回覆「本來就開著」比「開好了」誠實且省一次誤操作
- 對應 feedback：feedback_memory_can_lie（外延：別人的記憶也會說謊）
