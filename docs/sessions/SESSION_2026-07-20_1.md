## delta

進場前以為：把 geo 的資安 CI 複製到 UDN/ailiveX 是格式活——改 target URL、貼 yaml、pin SHA、收工。
現在理解：**給既有成熟平台接 CI，CI 的第一份工作是盤存量債，而不是防新錯**。難的不是寫 yaml（那是確定性格式活），是掃描器一上線照出的每個既有問題怎麼 triage——而 triage 是判斷活、且會碰 live 生產服務（ailiveX 的語音 agent 共用 image、改壞打爛全版）和平行 session（v20 的 package.json）。所以我在 ailiveX 停下來把三路處理攤給 Adam 點頭，沒有擅自 baseline 掉他 live 平台上的真安全 finding。
移動原因：同一份模板，geo（我自己剛蓋、乾淨）一次過，ailiveX（成熟、多人、live）照出 5 個既有問題，逼我把「接 CI」從格式活重新理解成判斷活。
違背了哪條 feedback：無違背。反而 feedback_surface_technical_debt（發現債要說不能默默繞）＋feedback_flagged_risk_must_be_verified（本機通≠CI通，寫完 workflow 重跑 semgrep）＋鑑別信號天條（每站都等 CI 真綠＋手動 dispatch 驗 DAST，不靠「我寫了 yaml」）全被正向實踐。

## 心法狀態

- 「機器把關不靠自律」第二/三次落地：CI 照出的都是我/別場沒自覺的存量債（3 Dockerfile root＋2 npm high），沒有一個是靠自省抓的
- 「宣告修好前指鑑別信號」全程主角：nosemgrep 放前一行→重掃驗證真的壓掉（不假設）；worker USER→build 跑 whoami=node（不假設）；CI→等 gh run conclusion=success＋手動 dispatch 驗 DAST（不靠「push 了就算」）
- 「pinning test 變紅＝正常運作」第二站實踐：Semgrep 抓 Dockerfile/npm high 是對的，我修真的（USER）或顯式記債可見（D8 annotation），沒關規則剪警報線
- 「發現債要說不默默繞」＋「降標準要 Adam 點頭」：ailiveX 的 baseline 決策攤開給他，不靜默弱化 gate

## 教訓

### L1：接既有平台的資安 CI，先照出的是存量債——triage 是判斷活，分三路
現象：同一份 geo 模板，UDN 照出 1 個（worker Dockerfile root）、ailiveX 照出 5 個（3 Dockerfile root＋2 npm high）。都是既有問題，非我新引入。
根因：新平台（geo 剛蓋、我控制全部）沒存量債；成熟平台累積了未接 CI 期間的債，掃描器一上線全曝光。
下次：接既有平台 CI 前先本地預跑一輪看存量債規模；triage 三路——①安全可修（node worker USER）修源碼＋build 驗；②碰 live 服務/撞平行 session（Python 共用 image、v20 package.json）記債＋inline nosemgrep 不擅改；③要降 gate 標準顯式＋CI 可見（continue-on-error 讓 finding 浮 annotation）＋記債＋觸發條件。三路都不靜默。
對應 feedback：feedback_surface_technical_debt＋pinning test 變紅＝正常運作。

### L2：Dockerfile 的 nosemgrep 要放 CMD 前一行（不能 inline），且必須重掃驗證
現象：Docker 不支援 CMD 行尾 inline 註解（會被當指令一部分），所以 nosemgrep 只能放前一行。
根因：semgrep 支援「同行或前一行」的 nosemgrep；Dockerfile 只能用前一行。
下次：放前一行後**必重掃確認 finding 真的消失**（本場重掃 0 findings 才確認生效），不假設語法對就生效——鑑別信號的 nosemgrep 版。
對應 feedback：feedback_flagged_risk_must_be_verified。
