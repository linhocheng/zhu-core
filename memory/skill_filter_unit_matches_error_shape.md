建過濾器/黑名單/validator 前，先問一句：**「這個錯誤的最小完整形狀是什麼？」** 攔截單位選錯，不是誤殺就是漏抓。

**Why**：2026-07-02 ailivex podcast 文字過濾器。Adam 要擋「鬆了一點/緊了一點」類 AI 詞，最直覺是把「鬆緊重輕」列黑名單——但「螺絲鬆了」「這箱子很重」是正常人話，單字黑名單必誤殺。AI 味的真實形狀是**句型**：「模糊主語（好像有什麼/心裡某處）＋體感動詞」。升級成 pattern 後，「好像有什麼鬆了一下」抓到、「那個『我』自然就鬆了」（主語具體，禪語）正確放行——同一個「鬆」字，一抓一放，證明單位對了。

**三個配套設計（一起用才完整）**：
1. **改寫範圍鎖死踩雷處**：LLM 只准重寫被標的那句，其他字不動——已經做對的東西（角色感 100%）不能被「順手潤稿」洗掉。
2. **改寫指令＝逼它交出背後的具體事件**：「這種『鬆』的背後一定有一個具體事件，用角色的話直說」（Adam 原話就是規格）。刪詞是消毒，錨定事件才變人話。
3. **過濾釘在入史前**：LLM 會模仿上下文，踩雷句一進對話歷史就會帶壞後續輪次。每輪生成完→掃→改寫→才 push history，污染不擴散。

**How to apply**：要建任何「擋壞輸出」機制時，先收集 5-10 個真實壞例＋5-10 個容易誤殺的好例，找出壞例共有、好例沒有的**結構特徵**——那才是攔截單位。然後跑抓/放雙向測試（該抓的全抓＋正常的全放）才算詞庫成立。

**觸發信號**：想列黑名單的時候；「把這個詞擋掉」類需求；過濾器上線後開始誤殺正常內容。
