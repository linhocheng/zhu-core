walking skeleton / 一吋蛋糕的驗收路徑，**必須從「使用者實際能把必要輸入送進去」開始**，不能把輸入當 happy-path 假設它會自己到。

**Why:** 2026-06-12 ailivex v5 多角色語音圓桌。機制（一房多 agent + 導演傳棒 + 單一發言）solo 路徑驗通，但「誰上桌」(roster) 要 Adam 在網址手貼一長串 characterId，手機一直掉，連測三次都只有一個角色 → Adam 體感「其他角色完全沒反應、gg」，其實是**人根本沒進房間**。最關鍵也最笨的那一關沒做，上面堆再多機制都沒人吃到。

**How to apply**（2026-08-07 動作化升級）：交付任何 MVP／新介面前，**自己當一次使用者，從最笨的入口實際走一遍，把每一步貼出來**（點哪裡→填什麼→看到什麼）。

- 手機/語音場景要用**該場景的入口**走，不能用 curl 代替——`curl` 通不代表手指在手機上按得到（2026-06-12 roster 手貼 characterId 就是這樣掉三次）
- 走不完就是入口沒做完，**不准交付**；真的沒法走（需要真機/真帳號）就在交付訊息明寫「入口未實走」
- 原姿態版（先問「使用者要怎麼塞輸入」）留作理由：那一問我永遠答得出漂亮答案，實走才會撞到「手機一直掉」

**觸發信號:** 準備說「機制通了你試試」；驗收路徑的第一步是我已經備好的資料而不是使用者的動作。與 `feedback_interface_blood_vessel_check`（出口）、`feedback_one_inch_cake_mvp` 同源，這條補**入口**那一端。
