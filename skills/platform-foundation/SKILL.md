# Platform Foundation — 平台地基 SOP v1.0

> 母版藍圖（11 章地基＋檢查表＋技術債規則＋承重牆帳＋滾動規則）：同目錄 `BLUEPRINT.md`。
> 本檔只管「怎麼執行」。

## 觸發判準

- **觸發**：Adam 提出從零蓋一個新平台／新系統（不限「平台」二字，任何會長出
  帳號、資料庫、部署的獨立系統都算）
- **也觸發**：既有平台發生「對外開放／開放註冊／大改版」——不走全流程，
  直接回該 repo 的 `FOUNDATION.md` 重算到期項；沒有帳本就補建一份（現況盤點式）
- **不觸發**：加功能到既有平台、fix、單檔工具腳本

## 流程

### STEP 1：讀母版，做開工調度清單

讀 `BLUEPRINT.md`，結合這次需求，把 11 項地基填成調度表：

- 每項標建議狀態：**首期灌／排後（帶觸發條件）／砍掉（帶理由）**
- 觸發條件用 BLUEPRINT 第十二章的默認最晚灌注點起手，按需求調整
- 一吋蛋糕照跑：蛋糕本身就是調度決策之一，記在表裡

### STEP 2：清單給 Adam 過目，點頭才動工（硬步驟）

用大白話講（不是技術清單轟炸）：「這次我建議首期灌這幾項、這幾項排到 X 之前補、
這幾項砍掉因為 Y——你看行不行」。**他點頭前不動工**（沒說動手就不動手照舊）。
砍掉和排後都要他明確同意，沉默不算。

### STEP 3：開工第一個 commit 帶上帳本

在平台 repo root 建 `FOUNDATION.md`，內容＝點頭後的調度表。模板：

```markdown
# FOUNDATION — 平台地基帳本
> 母版：~/.ailive/zhu-core/skills/platform-foundation/BLUEPRINT.md v1.0
> 規則：狀態只有 已灌/排後/砍掉。排後必帶觸發條件＋點頭日期；砍掉必帶點頭日期。
> 需求變動第一動作是回這裡重算到期；lastword 盤點到期項。

## 地基狀態
| # | 地基 | 狀態 | 觸發條件（排後必填） | 點頭 | 備註 |
|---|---|---|---|---|---|
| 1 | 身份與門禁 | 排後 | 第一個非內部用戶前 | 2026-MM-DD | dev 期先 basic |
| 2 | 資料憲法 | 已灌 | — | — | schema 在 lib/types.ts |
| … | | | | | |

## 技術債帳
| 債 | 利率 | 清償事件 | 記錄日 | 狀態 |
|---|---|---|---|---|

利率：活血=立刻清｜壓底=動工前清｜低利=順手清或顯式養著。
同一繞法連續兩場 session 被重新解釋 → 自動升高利貸，下場優先。
顯式養著的債雙向保護：不順手修（要 scoped 討論）、不挖深；退場條件寫進 code 註釋。

## 承重牆帳（無聲消失會打到真人的規則）
| invariant | 基線值 | 來源 commit | code anchor | pinning test |
|---|---|---|---|---|

pinning test 變紅＝系統在正常運作；禁 skip/xfail/刪測讓 CI 綠。
動承重牆檔案的改動要聲明 preserved / moving baseline。無測試守的標 prose-pinned。

## 變動記錄
- YYYY-MM-DD 需求「開放註冊」→ #4 濫用防護 排後→到期
```

### STEP 4：施工中滾動

- 需求變動 → **先回帳本重算**（哪些排後項升級到期），再改 code
- 發現技術債 → 當場記進技術債帳（標利率＋清償事件），不默默繞過
- 觸發條件到期而地基未灌 → 當場報 Adam，排進當前工作，不留到「以後」

### STEP 5：收尾節拍（接 lastword）

lastword STEP 0 清點時，本場施工的 repo 若有 `FOUNDATION.md`：
盤一遍**到期項**（排後觸發條件已到而未灌、高利貸債）→ 有就寫進 session 檔「未解」＋
下一步優先。這步已寫進 last-words skill。
